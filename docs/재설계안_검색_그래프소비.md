# 재설계안 — 법령·판례 검색, 임베딩, 그래프 소비 (2026-11-08, 사용자 승인)

사용자가 2026-11-08에 승인했다. 이후 설계서 §7·§8·§14와 구현지시서에 옮긴다. 생산 계층(수집·스키마·적재)의 바뀌는 점은 저장소 밖 비공개 설계에 적는다.

근거로 쓴 조사 세 가지(저장소 밖): 변호사시험 판례 검색 기록, 기존 법령·판례 검색 흐름과 실측, 지식그래프 소비 쪽 미구현 목록.

## 0. 목표와 성공 기준

- 목표: 기존 두 방식(이전 회사 검색, 지금 이 저장소의 검색)보다 빠르고, 질문한 사안에 맞는 법령·판례가 나오게 한다.
- 성공 기준(같은 표본으로 셋을 비교):
  - 정답 조문·판례가 상위 5개·10개 안에 드는 비율과 첫 정답의 순위가 두 방식보다 높다.
  - 지연(중간값·95% 지점)이 두 방식보다 짧다.
  - 법원 판단이 아닌 문단(배척된 주장, 반대의견)을 근거로 가져온 수가 0이다.
- 표본:
  - 변호사시험 선택형 공법 문항 중 행정법 문항. 문항마다 정답 조문·판례를 붙인다.
  - 행정법 사안 문제 표본(사안 → 정답 조문·판례). 정답은 사람이 확인한다.
  - 사건번호·조문 번호로 묻는 질의 표본(바로 찾기 확인용).

## 1. 모듈 경계

새 기능을 덧대지 않고, 바뀌는 곳이 한 모듈 안에 머물도록 나눈다.

**crates/retrieval**

| 모듈 | 맡는 일 | 늘릴 때 |
|---|---|---|
| `query` | 질의 해석: 사건번호, 법령 약칭과 조문 번호 찾기, 낱말 정규화(조사·어미 떼기, 흔한 낱말 거르기) | 규칙 표에 줄 추가 |
| `candidates` | 후보 생성기들. 모두 같은 꼴(입력: 해석된 질의와 거름 조건, 출력: 순위 붙은 후보)로 만든다 | 생성기 파일 하나 + 등록 한 줄 |
| `fuse` | 생성기 결과를 RRF로 합침. 생성기별 가중치는 설정값 | 설정값만 |
| `rerank` | 선택 단계: 질문의 사실과 후보 판례의 기초사실 문단을 비교해 순위를 다시 매김 | 측정으로 효과가 확인될 때만 켬 |
| `assemble` | 결과를 판례 단위로 묶고(판례당 판단 단위 최대 3개), 판결요지·표지(말한 쪽, 변경된 판례)를 붙임 | 표지 종류는 등록표 |
| `version` | 기준일 조문 고르기(아래 3절) | — |

**crates/kg**

| 모듈 | 맡는 일 | 늘릴 때 |
|---|---|---|
| `shapes` | 모양별(개념 틀, 나무, 흐름 …) 줄 풀기. 모양 이름으로 고르는 등록표 | 새 모양은 파일 하나 + 표 한 줄 |
| `contract` | 묶음 머리의 계약을 읽음: 관계 목록, 허용된 두 단계 경로, 상태 값 | 생산 쪽 계약만 바뀜 |
| `fields` | 근거·뜻풀이가 들어 있는 칸 경로를 모양별 표로 | 표 한 줄 |
| `traverse` | 펼치기: 허용된 두 단계 경로만, 응답 상태 다섯, 기준일 판단 | — |
| `index` | 그래프 사이 색인, 조문 번호(판본 표 번호) 풀기 | — |

**crates/server**: 보기 함수와 HTTP는 모양을 모르는 공통 꼴만 다룬다.
**에이전트 도구**: 검색 도구 인자에 사건번호·조문·기준일·「법원 판단만」을 더하고, 지식그래프 도구에서 상태 칸이 없으면 「모름」으로 찍던 기본값을 없앤다.

## 2. 판례: 판단 단위와 표지

- 판결을 절 → **문단**으로 나누고, 문단마다 세 가지를 붙인다.
  - 말한 쪽: 법원, 원고, 피고, 원심, 청구인
  - 의견 종류: 다수, 별개, 반대, 보충
  - 받아들였는지: 받아들임, 배척, 해당 없음
- 붙이는 방법: 구조 표지(「가. 원고의 주장」 「나. 판단」 「~라고 주장한다」 「받아들이지 않는다」 「대법관 ○○○의 반대의견」)로 코드가 먼저 정한다. 표지가 없는 문단만 모델에 한 번 묻고, 근거 문구를 원문 그대로 인용하게 해 코드가 대조한다. 대조가 안 되면 「미상」.
  - 이 분류는 저장 경로에 붙이기 전에 표본으로 잘못 분류한 수와 놓친 수를 잰다.
- **판단 단위**: 판결요지 항목을 그 항목과 가장 가까운 법원 판단 문단에 잇는다. 검색은 이 판단 단위(판결요지 항목 + 법원 판단 문단)로 한다. 판결요지가 없는 하급심은 법원 판단 문단만.
  - 근거: 만점 실행은 판결요지 항목을 본문 단락에 맞춘 단위로 찾았고(사건당 3개), 같은 25문항에서 여러 크기 단위를 합친 방식(22/25)보다 나았다(23/25).
- 배척된 주장과 반대의견은 기본 후보에서 뺀다. 요청하면 찾되, 인용할 때 코드가 「원고 주장(배척됨)」 「반대의견」 표지를 반드시 붙인다.
- 판결요지는 법원도서관의 편집물이므로, 근거로 인용할 때는 이어진 법원 판단 문단(본문)을 앞세운다.

## 3. 법령: 판본과 시행일

- 판본은 통째로 저장하되, **기준일이 있으면 조문(논리 키) 단위로** 고른다: 같은 논리 키의 단위 가운데 실제 시행일(단위 시행일, 없으면 판본 시행일)이 기준일 이하인 것 중 가장 늦은 것.
- 부칙의 조문별 시행일은 API의 조문 시행일과 부칙 예외 문장 해석으로 단위 시행일에 넣는다. 계산할 수 없는 문장(「대통령령으로 정하는 날」)은 미정으로 둔다.
- **현행 조문 표**를 따로 둔다(기준일 없는 질의용). 근거: 현행 판본만 담은 표로 바꾸자 상위 10건 적중률 80.2% → 95.5%, 지연 780ms → 29ms(이전 회사 검색 실측).
- 현행 질의에서 아직 시행 전인 조문은 본문 옆에 「시행 예정: 날짜」를 붙인다.

## 4. 후보 생성기 (사안에 맞게)

| 생성기 | 하는 일 | 근거 |
|---|---|---|
| 바로 찾기 | 사건번호 → 판례, 법령 약칭+조문 번호 → 조문 | 이전 검색에서 사건번호 질의가 벡터·글자 모두 0건 → 바로 찾기로 24/24 |
| 인용 경로 | 질문의 쟁점에서 고른 조문(요건 트리의 근거 조문, 법령 검색 결과)을 인용하고 배척하지 않은 판례만 모아, 그 안에서 질의 벡터로 순위 | 이전 측정에서 이 거름은 맞는 판례 11건을 하나도 잃지 않음 |
| 글자 | 정규화한 낱말로 찾음. 색인 방식(형태소 사전, 두 글자 조각, 지금의 trigram)은 표본으로 재서 고름 | 지금 방식은 「취소를」과 「취소」가 0.5로 문턱 0.6 미달 |
| 벡터 | 판단 단위·조문 임베딩, 필터와 함께 쓰는 HNSW | 아래 5절 |

- 거름: 심급, 선고일 ≤ 기준일, 분야는 선택(기본으로 걸지 않음 — 이전 측정에서 맞는 형사 판례 5건을 잃음), 변경된 판례는 표시하고 변경한 판례를 함께 낸다.
- 질의 하나에 쿼리 재작성 모델 호출은 두지 않는다(이전 실측 1~2.8초). 쟁점 해석은 메인이 이미 하고, 생성기는 코드다.

## 5. 임베딩과 색인

- BGE-M3, 1024차원, `halfvec(1024)`.
- 임베딩할 글 앞에 짧은 머리를 붙인다(예: `[대법원 2021두1234 · 판단 · 법원]`).
- 법령은 **글자 내용의 해시로 한 번만** 임베딩하고 판본들이 나눠 쓴다(해시를 키로 한 임베딩 표). 이전 검색에서 상위 30건이 같은 조문의 다른 판본으로 찬 문제를 막는다.
- 대량 임베딩은 Colab 대량 방식(여러 개의 `.jsonl.gz` → `.npz`), 질문 하나의 임베딩은 서버 방식.
- 색인: HNSW 코사인(`m=16`, `ef_construction=128`), 적재를 마친 뒤 만든다. 질의 때 `hnsw.ef_search`와 `hnsw.iterative_scan = relaxed_order`를 걸어 필터 때문에 후보가 비는 것을 막는다.

## 6. 그래프 소비 (가져올 순서)

| 순위 | 할 일 | 모듈 | 지금 묶음으로 잴 수 있나 |
|---|---|---|---|
| 1 | 허용된 두 단계 경로만 펼치기(계약의 허용 경로 403개) | kg `traverse`·`contract` | 예 |
| 2 | 근거·뜻풀이 칸을 모양별 표로(개념 틀은 간선의 책 근거, 기록 안의 뜻풀이) | kg `fields`, server 보기 | 예 |
| 3 | 상태 칸이 없으면 「모름」으로 찍던 기본값 없애기 | 에이전트 도구 | 예 |
| 4 | 응답 상태 다섯(찾음·없음·모름·범위 밖·아직 안 봄) | kg `traverse` | 예 |
| 5 | 접힌 줄(나무·흐름 모양), 옛 id 대응표, 시작 단계 선언 읽기 | kg `shapes` | 해당 묶음이 와야 |
| 6 | 판본 표 번호 풀기와 조문으로 찾기(도구는 법령+조문, 서버는 같은 키) | kg `index`, server, 도구 | 해당 묶음이 와야 |
| 7 | 서명 확인 | kg, 설정 | 공개 키가 있어야 |
| 8 | 기준일 판단 | kg `traverse` | 예 |
| 9 | 그래프 사이 색인 | kg `index` | 묶음이 둘 이상이어야 |
| 10 | 카탈로그 보강, 묶음이 바뀔 때 짧은 번호표 처리 | server | 예 |

- 가져오지 않는 것: 위임망 소비(사용자 지시), 이름 글자로 잇는 준용·갈래 이음, 효과를 재지 못한 검색 앞 관문.

## 7. 평가 장치

- 평가 실행기(Rust bin)를 둔다. 표본 파일과 정답은 저장소 밖에 두고 경로만 받는다.
- 같은 표본을 세 방식(이전 회사 검색 결과는 기록된 실측값으로, 지금 검색, 새 검색)으로 돌려 0절의 지표를 낸다.

## 8. 순서

1. 평가 표본과 실행기
2. 생산: 스키마 고침(문단 표지, 판단 단위, 현행 조문 표, 해시 임베딩 표) → 법령 수집
3. 법령 검색(바로 찾기, 조문 단위 판본, 현행 표, 글자 색인 실측) → 측정
4. 판례 수집 → 문단 표지(정확도 측정) → 판단 단위
5. 판례 검색(인용 경로, 벡터, 합치기, 판례 단위 묶기) → 측정
6. 그래프 소비 1·2·3·4·8·10 (지금 묶음으로 바로 잼)
7. 나머지(5·6·7·9, 재순위)

## 9. 사용자 결정 (2026-11-08)

1. 평가 표본의 정답은 **출처가 준 정답만** 쓴다(사람이 새로 붙이지 않는다). 예: 변호사시험은 법무부 최종정답, 판례는 공보·법제처가 단 참조조문·참조판례.
2. 사실관계로 순위를 다시 매기는 단계는 **측정한 뒤** 넣는다.
3. 사건 진행 상태 소비를 **넣는다**. 다만 이 서비스는 사건 객체가 없으므로(2026-11-07 결정), 진행 상태는 대화(세션) 안에서만 유지하고 사용자 설정 Store에는 넣지 않는다.
