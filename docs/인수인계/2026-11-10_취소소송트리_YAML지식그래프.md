# 취소소송 요건 트리, YAML 지식그래프 소비, 나무 판정 도구 (2026-11-10)

## 사용자 결정

- 취소소송 요건 트리를 만든다. 입증책임은 판례 입장을 따른다. 처분이 적법하다는 것은 처분청(피고)이 입증하고, 재량권 일탈·남용은 원고가 입증한다.
- 생산 쪽이 낸 행정법·취소소송 지식그래프(요건 나무, 개념 틀)를 YAML 원본 그대로 소비한다. 노드 id로 찾는 표와 출발 노드별 간선 목록을 먼저 만들어 둔다.
- 탐색 기본 연산은 expand 하나다. 판정은 순수 함수 두 개가 한다. 하나는 나무를 판정하는 함수, 다른 하나는 상태를 접는 함수다.

## 취소소송 요건 트리 (원본 YAML은 저장소 밖)

- 모양은 설계서 §9.4를 따랐다.
  - 소송요건: 처분성 4징표, 원고적격(처분 상대방 / 제3자의 법률상 이익), 제소기간, 협의의 소의 이익
  - 본안 위법성: 절차 하자, 법률유보 위반, 재량 하자
  - 사정판결: 항변
- 노드 36개, 간선 36개, 리프 23개이고, `ruleloader check`를 통과했다.
- 처분청이 입증할 적법 사실은 위법 사유 노드의 항변(defense)으로 둔다. 사전통지를 함, 근거와 이유를 제시함, 근거 법률이 있음이 여기에 든다. 입증되지 않으면 입증책임을 적용한 결론에서 위법 사유가 성립한다.
- 제소기간 리프 두 개는 기간 계산 리프다.
  - 안 날부터 90일: `within_days`
  - 있은 날부터 1년: `within_years`
- 근거 구절 44개는 모두 코퍼스 DB의 현행 조문 원문과 글자까지 같다.

## 바꾼 것

- kg
  - `src/source.rs`(새 파일): `$KG_DIR/source/<묶음>/`의 YAML 원본 묶음을 읽는다.
    - `legal_build.yaml`의 서명을 확인한다.
    - `legal_build.yaml`의 「파일」 sha256과 계약·타입·그래프 파일이 같은지 확인한다.
    - 그래프 파일을 항목 단위로 나눠 읽어(한 번에 전부 올리지 않음) 기존 SQLite 표(노드, 간선)에 올린다.
    - 모양은 `types.yaml`에서 정한다. 판정 관계 무리는 「나무」, 개념 틀은 「연결망」이다. 상태 값도 `types.yaml`의 읽는 모양 절에서 가져온다.
  - `src/tree.rs`(새 파일)
    - `KgSet::tree`: expand를 되풀이해 뿌리부터 element·defense·rebuttal을 모은다.
    - `fold`: AND·OR를 충족·불충족·모름·주장됨 네 값으로 접는다.
    - `judge`: 충족인 항변·재항변이 그 노드를 막는다.
  - 다른 이름(aliases)으로도 찾는다. 새 표 `names`에 넣고, 이름 FTS에도 함께 넣는다.
  - 적재기 판을 3으로 올렸다. 기존 SQLite는 한 번 다시 만들어진다.
  - 소비용 폴더가 없어도 원본 묶음은 읽는다.
- server
  - `POST /sessions/{sid}/kg/tree`(`http/kgtree.rs`): 뿌리 번호와 잎 상태를 받아 나무를 접는다.
  - 응답에는 노드마다의 값, 막은 항변, 아직 정하지 않은 잎이 들어간다.
- agent
  - 도구 `kg_judge_tree`를 더했다. 이 대화에 `kg_write_state`로 적은 그 그래프의 상태를 모아 보낸다.
  - `kg_write_state`가 근거를 거절할 때, basis에 넣을 수 있는 올린 문서 이름을 함께 알려 준다.
  - 시스템 지시에 개념 틀과 요건 나무의 탐색 순서를 넣었다.

  - server: 지식그래프 시험 7개 통과
  - agent: `test_kg_tool.py` 8개, `test_answer_gate.py` 통과
- clippy(`kg`, `server`, 시험 포함): 이번 변경 부분의 경고는 0이다. 나온 경고 1개는 손대지 않은 크레이트에서 나왔다.
- 실제 묶음 적재
  - 요건 나무: 노드 143, 간선 128. README의 수와 같다.
  - 개념 틀: 노드 29,966, 간선 31,064
  - 꺼진 묶음 0개
  - 판을 올린 뒤 첫 기동은 98초였다. 기존 묶음도 다시 만들었기 때문이다. 기동 뒤 서버 메모리는 77MB였다.
- 게이트웨이를 거친 E2E(지어낸 영업정지 처분서)
  - 취소소송 판정: 8.7초
    - 결론 유보 / 입증책임을 적용한 결론 불성립
    - 제소기간 두 리프는 문서의 송달일·처분일·제소일로 계산해 참
    - 원고적격(처분 상대방) 리프는 모델의 인용이 문서 원문과 달라 판정 불가
  - 개념 틀 + 요건 나무 질문: 12.8초
    - `kg_find` 두 번과 `kg_expand` 한 번으로 「처분」 개념과 「처분의 효력」 뿌리를 읽고 답했다.
    - 잎 상태 적기와 `kg_judge_tree`는 이번 실행에서 모델이 부르지 않았다.

## 남은 일

- 원고적격 리프의 인용이 어긋난 이유는 아직 보지 않았다. 서버가 실패한 인용문을 기록하지 않는다.
- 「인용될 수 있나?」 같은 질문은 판정 자동 연결 규칙의 질문 형태에 들지 않는다. 그런 질문에서 모델이 판정 도구에 잘못된 인자를 넣어 400이 났다.
- 요건 나무에는 「취소소송 제기」 뿌리가 없다. 그 이름은 「집행정지 결정」 아래의 잎이다.
