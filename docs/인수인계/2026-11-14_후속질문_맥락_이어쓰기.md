## 왜

2026-11-13 밤 대화에서 「클럽 마약 방치 제재 근거」 뒤에 이어진 「무슨 법?」·「무슨 조례?」·「강남구 단란주점」이 앞단 판정기에서 「법률 아님」으로 판정돼 조사 없이 기억으로 답했고, 「아니 시발 무슨 조례」는 조사 지시문이 그 글자뿐이라 조례 일반론(지방자치법 제28조·2022추5118)으로 「존재하지 않는다」고 단정했다. 같은 날 다른 질문은 토큰 예산(30만)에 걸려 「제한에 걸려 중단됨」으로 끊겼다.

- 다시 답변하기: 에이전트 `POST /session/{id}/retry`가 마지막 질문(올림 표시·요약 메시지 제외)과 그 뒤 메시지를 체크포인트에서 지우고(`RemoveMessage`), 저장된 답도 지운 뒤 같은 질문을 새 request_id로 다시 실행한다. 게이트웨이 `/session/{id}/retry`, 화면은 마지막 답 아래 버튼. 서버 쪽 읽기 기록은 대화 단위라 그대로이고, 다음 단계 기록은 request_id로 차례를 가르므로 재조사 규칙이 새로 적용된다. 가짜 모델 끝에서 끝 시험(질문→다시 답변→기록에 질문 1·답 1) 통과.
- 컨텍스트바: 주 모델 마지막 호출의 입력+출력 토큰을 `Turn.context_tokens`에 두고 `Usage` 이벤트에 `context`·`context_limit`(설정 `MODEL_CONTEXT_TOKENS`, 기본 32,768)·`summary_at`(요약 발동 20,000)을 실어 보낸다. 게이트웨이는 `Usage`를 사용량 집계로만 남기고 화면에는 `Context` 프레임(used·limit·summary_at)만 전달한다. 화면은 대화 머리 아래 띠 「문맥 N / 32,768」와 요약 기준 눈금을 보이고, 저장된 답에도 `context`를 넣어 새로 열어도 마지막 값이 보인다. 게이트웨이 실측 1회: 새 대화 첫 질문 뒤 used 12,994.
- 올린 파일 칩: 끝난 칩(올렸습니다·실패·멈춤)은 다음 질문을 보낼 때 자동으로 치운다. x는 그 전에 손으로 치우는 용도.
- 대답 큐잉: 게이트웨이가 같은 대화·같은 사용자의 질문을 409/429로 거절하지 않고 앞 답이 끝날 때까지 기다린다(`ask_queue_wait` 300초 = 질문 시한; 전체 동시 4개 상한은 30초 대기 뒤 거절 유지). 자리가 없으면 먼저 `Status` 「앞 질문의 답을 기다리는 중」을 보내고 자리를 얻은 뒤 에이전트에 보낸다. 화면은 답을 받는 중에도 질문을 보낼 수 있고 기다리는 차례는 그 상태 문구를 보인다. 게이트웨이 단위 시험 37(대기열 4), DB가 필요한 통합 시험은 이 기계에 시험 DB 변수가 없어 아직 안 돌렸다.

## 학칙·조례 (11-14 저녁)

- 학칙(단국대, A안): 사용자가 받아 준 전체 연혁 묶음(학칙 102판·시행세칙 76판, hwp)을 텍스트로 바꿔(pyhwp, 저장소 밖 도구) 법령 API 모양의 JSON으로 만들고, 비공개 생산자의 장부 경로로 law 표에 kind `rule`(law_type 학칙·학칙 시행세칙)로 넣는다. HWP 3.0 형식 49판(1947~2010년대)은 pyhwp가 못 읽어 뺐고 128판(학칙 66·세칙 62)이 들어간다. 소비 쪽 변경: 인용 관문 이름 꼬리에 학칙·세칙(「」 안·맨이름·조문 앞), 질문 낱말에 학칙·세칙, 별칭 파일에 「학칙」·「단국대 학칙」·「학칙 시행세칙」→정식 이름. 검색 가중치는 kind `rule`을 부령과 같은 셋째 값(지금 설정 0.6)으로 두었다(`retrieval::LawWeights`; 전에는 ELSE 0.3). 적재 결과: law 2건, 조문 행 1,157, 조문 단위 4,057, 현행 조문 학칙 118·시행세칙 82(판 이력 학칙 2011-02-24~, 시행세칙 2009-08-31~). 키워드 색인을 다시 만들어(`bigram-v1-20261114-hakchik`, 단위 4,228,581·별표 조각 1,371,178, 180초) `server.env.sh`의 `CORPUS_KEYWORD_INDEX`를 바꿨다. 글자 검색만으로(임베딩 서버 꺼짐) 「단국대학교 학칙 휴학」 상위 8건 중 1·2위가 학칙·시행세칙 제1조, 「단국대학교 학칙 제4조」는 제4조가 1위, 「학칙 수업연한」은 고등교육법이 앞서고 학칙 제4조는 8위 안에 없음. `/laws/unit`은 정식 이름·별칭(학칙) 모두 조문을 돌려줌. 임베딩과 질문 시험은 GPU를 다시 켠 뒤.
- 조례(자치법규): 생산자에 kind `ordin`(법제처 target=ordin) 수집·파싱 경로를 넣었고 DB 종류 제약을 ordin·rule까지 넓혔다. 법제처 API가 11-14 21:00까지 점검이라 수집은 그 뒤. 1차 범위는 서울특별시 조례(환경 변수 `ORDIN_ORGS`·`ORDIN_KINDS`). 자치법규 API 응답 키는 문서 기억으로 추정해 넣었으므로 첫 호출에서 맞춰야 한다. 조례가 들어오면 `holdings`의 「조례는 자료에 없음」 안내는 자동으로 꺼진다.

## 규범 종류 명세 모듈 `crates/norms` (11-14 저녁)

- 왜: 학칙을 넣으면서 인용 관문·질문 낱말·검색 가중치·자료 범위 안내·근거 칩을 각각 고치고 있었다. 사용자가 「법률과 학칙은 다른데 누더기 패치」라고 지적해, 규범의 종류를 한 곳에 적고 모든 구성 요소가 그것을 읽는 구조로 바꿨다. 조례도 같은 틀에 넣었다.
- 명세(`crates/norms/src/lib.rs`, 의존 없음): `NormKind { kind, label, rank, tails, words, bare, weight, missing_note, scope_line, writing_note }` 네 종류 — `law` 법령(꼬리 법률·법·령·규칙), `admrul` 행정규칙(고시·훈령·예규·지침·규정), `ordin` 자치법규(조례·자치법규; 자료에 없을 때 안내문·범위 줄·작성 지시), `rule` 기관 규정(학칙·세칙; 작성 지시). `bare`는 맨이름을 어떻게 검사하는지다: `Checked`(법령·기관 규정: 읽은 것과 대조), `RegionOnly`(자치법규: 지역 이름이 앞에 붙을 때만), `QuotedOnly`(행정규칙: 「」 안에서만 — 「규정」·「지침」은 보통 낱말이라 맨이름으로 잡지 않음). 함수: `kind`·`label`·`all_tails`·`tails_for(bare)`·`names_a_norm`·`kind_of_name`·`question_words`·`kinds_in_question`·`missing_kinds`·`is_missing_note`·`writing_notes`·`weight_slot`.
- 읽는 곳: citegate(이름 정규식 — 「」 안은 모든 꼬리, 조문 앞·맨이름은 `Checked` 꼬리, 조례는 `RegionOnly` 꼬리), retrieval `LawWeights::sql/of`(종류별 가중치 자리), server `holdings`(없는 종류 안내·작성 지시 `guidance_for`)·`known`(법령 이름→종류 `kind_of`, `names_a_norm`)·`check`(안내문 통과)·`next_step`(질문 낱말), `http/funcall`(응답 `StepReply.guidance`), gateway `filter`(근거 항목에 `norm` 라벨: 법령·행정규칙·자치법규·기관 규정·판례), 에이전트 접착(`ledger.Authority.norm_kind` ← 판 `kind`, `sources`의 `norm_kind`, `turn.guidance`를 시스템 메모로만), 화면(`Source.norm`을 근거 칩에 표시).
- 꼴(사용자 지시 「enum으로 맞춰」, 삼성 테크 블로그 article/37 「러스트로 디자인 패턴 시작하기」의 팩토리 메서드 꼴): 종류 열쇠는 `enum Kind { Law, AdminRule, Ordinance, Rule }`, 종류별 동작은 트레잇 `Norm`(label·rank·tails·words·bare·weight·missing_note·scope_line·writing_note)을 단위 구조체 `Law`·`AdminRule`·`Ordinance`·`Rule`이 구현, 공장 함수는 `Kind::from_db("rule")`(DB 값)·`Kind::of_name("단국대학교 학칙")`(이름 꼬리)·`Kind::norm()`(트레잇 객체). 쓰는 쪽은 `Kind`를 들고 다니고 DB·JSON 경계에서만 `db_value()`·`from_db()`로 바꾼다(`KnownLaws::kind_of → Option<Kind>`, `guidance_for(question, Kind들)`, `LawWeights::of`는 DB 문자열을 받아 `from_db`). 표 구조(`KINDS` 배열)는 없앴다.
- 첫 시도의 실수: 꼬리를 한 묶음으로 쓰자 「국가배상법 제2조 제1항이 기본 규정입니다」의 「기본 규정」, 「관련 조례에 따릅니다」의 「관련 조례」가 맨이름으로 잡혀 막혔다(citegate 표본에서 잡힘). `bare` 정책을 명세에 넣어 고쳤다.
