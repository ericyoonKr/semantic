# 2026-11-13 연구 하위 에이전트: 법령과 판례를 함께 읽고 근거로 들기

## 바꾼 것
- **연구 지시문**(`agent/src/semantic_agent/agent/prompts.py`의 `RESEARCHER_PROMPT`만): 커밋 ce27b99에 들어간 「search_cases를 불렀으면 판례 1~3건을 반드시 read_case」 줄을 아래로 바꿨다.
  - 법령과 판례를 함께 근거로 든다. 처음 차례에 `search_laws`와 `search_cases`를 함께 부른다.
  - 쟁점을 정하는 조문 1~3개를 `read_law`로 읽고, 쟁점에 맞는 판례 1~2건을 `read_case(decision_id, sections=["holding_issue", "holding_summary"])`로 읽는다.
  - 판례는 판시사항·판결요지 두 절만 읽는다. 판례는 모두 3건까지만 읽고, 이미 읽은 판례·조문은 다시 읽지 않는다.
  - `found`에는 조문 근거 줄과 판례 근거 줄을 각각 1줄 이상 넣는다. 맞는 것을 찾지 못한 쪽만 `not_found`에 적는다.
- **단계형 연구 지시문**(`prompts_research.py`의 5단계, `RESEARCH_PROMPT=steps`일 때만 쓰임): 찾은 판례 가운데 쟁점에 맞는 1~3건을 반드시 `read_case`로 읽는다. `decision_id`가 어디 있는지 적었다. 이 지시문으로는 아직 안 쟀다.
- **판례 검색 결과 끝 안내**(`tools/search.py`의 `CASE_EXCERPT_NOTE`): 「쟁점에 맞는 판례 1~2건을 read_case(decision_id)로 읽어야 근거로 들 수 있다. decision_id는 항목 머리의 값이다」. 법령 검색 결과의 안내(`EXCERPT_NOTE`)는 그대로다.
- **`read_case` 설명**: `decision_id`는 `search_cases`·`case_citations` 결과 항목의 값이고, 읽은 결과에 근거 번호가 붙는다고 적었다.

## 왜
- 처음 잰 질문 1개에서 연구 하위 에이전트가 판례를 검색만 하고 읽지 않아 판례를 근거로 들지 못했다.
- 「판례 1~3건 반드시 읽기」를 넣은 뒤(커밋 ce27b99) 잰 결과, 판례는 읽지만 다른 문제가 드러났다.
  - 판례를 질의당 평균 5~7번 읽었다. 같은 판례를 한 질문 안에서 6번까지 다시 읽었다.
  - 판례를 절 지정 없이 읽으면 중간값 7,829자, 판시사항·판결요지만 읽으면 1,843자다(판례 8건으로 잼).
  - 16개 중 8~9개가 질문 토큰 예산(30만)을 넘겨 「제한에 걸려 중단됨: 토큰 예산」으로 끝났다.
  - 법령은 거의 읽지 않아(`read_law` 21~24번, `read_case` 90~110번) 법령 근거가 붙지 않았다.

## 잰 것
- **질문**: 사실관계가 있는 행정법 판단 질문 16개를 직접 썼다(아래 목록). 파일은 저장소 밖 작업 폴더의 `judge_questions.json`.
- **방법**: 에이전트 `/session/{id}/ask`를 내부 키로 직접 부름. 동시 2. 모델은 새 GPU(Gemma 26B).
  - Sources 이벤트에서 법령·판례 수와 검증 통과(`verified`) 수를 셈.
  - `read_law`·`read_case` 수는 검색 서버 기록에서 그 질문의 요청 ID로 `/laws/unit`·`/cases/{id}` 성공 요청을 셈.
  - 「확인하지 못한 근거」 안내 수는 답 글과 Warning 이벤트에서 셈.
- **성공 기준**: 같은 16개 질문에서 Sources에 법령과 판례가 함께(검증된 것) 붙은 질의 수가 고치기 전보다 많고, 법령 근거가 붙은 질의 수는 줄지 않는다.
