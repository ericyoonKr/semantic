# 2026-11-13 올린 파일의 원본 저장과 원본 보기

## 바꾼 것
- **세션 DB**(`crates/sessdb`)
  - 파일별 저장 부분에 `Part::Original`(키 `{세션}/doc/{파일ID}/original`)을 더했다.
  - `UploadParts`에 `original` 칸을 더했다. `put_upload`가 다른 부분과 같은 batch로 원본 바이트를 쓴다.
  - 세션 지우기(`delete_session`)는 `{세션}/`부터 `{세션}0` 앞까지를 범위로 지우므로 원본도 함께 지워진다. 시험으로 확인했다.
- **검색 서버**(`crates/server`)
  - 업로드 처리(`upload/pipeline.rs`)가 받은 바이트를 그대로 원본으로 저장한다. PDF는 글자 인식 작업자에게 넘기기 전에 사본을 하나 둔다.
  - `GET /sessions/{sid}/files/{file_id}/original`(`http/files.rs` `original`): 바이트, 원래 형식에 따른 `Content-Type`(pdf `application/pdf`, docx `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, hwpx `application/hwp+zip`), 퍼센트 인코딩한 파일 이름(`x-file-name`)을 돌려준다. 메타나 원본이 없으면 404.
- **에이전트**(`api/app.py`, `tools/client.py`, `tools/fake.py`)
  - `GET /session/{id}/files/{file_id}/original`: 파일 ID 형식(`FILE_ID`)과 그 대화의 업로드 목록에 있는지를 먼저 확인하고(`known_upload`), 검색 서버 응답을 흘려서 그대로 넘긴다. `content-type`·`content-length`·`x-file-name`만 넘긴다.
  - 도구 클라이언트에 바이트를 흘려받는 `open_bytes`를 더했다.
- **게이트웨이**(`crates/gateway/src/http/files.rs` 새 파일, `http.rs`)
  - `GET /session/{id}/files/{file_id}/original`: 본인 대화인지 확인, 파일 ID 검사(`chat::file_id_ok`), 에이전트 응답을 흘려서 넘긴다.
  - 머리
    - `Content-Type`: 위 세 형식만 그대로 두고 나머지는 `application/octet-stream`.
    - `Content-Disposition`: PDF는 `inline`, 나머지는 `attachment`. `filename`에는 ASCII만 남긴 이름, `filename*`에는 RFC 5987 인코딩 이름. 제어 문자·`/`·`\`는 뺀다.
    - `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`.
    - CSP: PDF는 `default-src 'none'; … frame-ancestors 'self'`, 나머지는 `… frame-ancestors 'none'; sandbox`. `X-Frame-Options`는 PDF `SAMEORIGIN`, 나머지 `DENY`.
  - `http.rs`: 경로 한 줄을 더했다. 그리고 전체에 붙는 `x-frame-options`·`content-security-policy` 머리를 「처리기가 정하지 않았을 때만 붙임」(`if_not_present`)으로 바꿨다. 바꾸지 않으면 PDF 응답에도 `DENY`·`frame-ancestors 'none'`이 덮어써져 화면 안 `<iframe>`에서 PDF가 열리지 않는다. 다른 처리기는 이 두 머리를 정하지 않으므로 그 응답은 전과 같다.
- **화면**(`web/src/features/upload/files.ts`, `UploadedFiles.tsx`, `app/styles.css`)
  - 파일 목록에서 `format`을 읽는다.
  - 「원문 보기」 창: PDF면 같은 출처 경로의 원본을 `<iframe>`으로 보인다. 그 밖의 형식은 지금처럼 추출한 글을 쪽 단위로 보인다(`RichBlocks` 그대로).
  - 창 머리에 「원본 내려받기」 링크를 둔다(모든 형식).

## 저장 크기
- 업로드 한도(`max_file_bytes`, 기본 200 MiB)는 그대로다. 원본을 저장하므로 세션 DB 크기는 파일마다 원본 크기만큼 늘어난다.
- 원본은 RocksDB 값 하나로 들어간다. 한도에 가까운 큰 파일은 쓰기 버퍼(64 MiB)보다 커서 그때마다 버퍼를 비우게 된다. 큰 파일이 잦으면 BlobDB 같은 큰 값 전용 저장을 검토해야 한다(아직 안 쟀습니다).
- PDF 업로드 중에는 원본 사본 하나만큼 메모리를 더 쓴다. 동시 업로드 수는 기존 `uploads` 제한을 따른다.
- 이번 변경 전에 올린 파일은 원본이 없어 원본 경로가 404다. 화면에서 PDF는 빈 창에 오류가 보일 수 있다.
