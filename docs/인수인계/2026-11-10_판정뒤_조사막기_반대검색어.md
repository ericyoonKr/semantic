# 2026-11-10 판정 뒤 조사 막기, 반대 검색어 대조 완화

## 왜 (실제 Gemma, 국가배상 질문 52초를 나눠 봄)
- 판정이 나온 뒤에도 주 에이전트가 조사 하위 에이전트를 둘 띄움: 모델 호출·검색으로 18초, 그 결과로 답 글에 판정에서 「모름」인 요건(고의·과실)을 「가능성이 있다」고 덧붙임.
- 하위 에이전트의 반대 결론 검색어를 「실제로 부른 검색어」와 글자 그대로 비교해 확인 실패 → 3회 되묻기(7초).
- 법령 글자 검색 한 건이 13초(별도 문제, 아직 안 고침).

## 바꾼 것
- `agent/src/semantic_agent/agent/judge_route.py`: 요건 판단 질문으로 고른 차례에서 judge 결과가 나온 뒤의 모델 호출은 `task`(하위 에이전트) 도구를 빼고, 「판정 문장과 필요한 사실 목록만으로 답한다, 판단하지 못한 요건을 추측해 덧붙이지 않는다, 더 조사하지 않는다」를 시스템 글에 붙인다.
- `agent/src/semantic_agent/agent/delegation.py`: 반대 검색어 대조를 공백·문장부호를 뺀 글자로 비교. 확인 실패 때 적어 낸 검색어와 실제 부른 검색어(마지막 6개)를 기록에 남긴다.

## 잰 것
- 같은 질문: 52.1초(첫 답 글 46.6초) → 6.5초(첫 답 글 2.6초). 판정 리프 캐시가 맞은 상태이며, 캐시가 없으면 판정에 15초쯤 더 든다. 조사 하위 에이전트 호출 2 → 0, 답 글은 판정 문장과 필요한 사실 목록만.
- 시험: `tests/test_judge_route.py`(판정 뒤 도구·지시), `tests/test_reverse_query.py`(공백·부호 무시, 다른 검색어는 거부) 포함 에이전트 시험 69개 통과.

## 남은 것
- 답 글이 판정의 첫 줄(입증책임 없이 「결론 유보」)만 옮기고 「입증책임을 적용한 결론: 성립」 줄을 빠뜨렸다. 판정 원문은 VerdictReady 사건으로 화면에 따로 간다.
- 판정 밖 추측을 막는 것은 지시문이라, 코드로 막는 장치는 아니다.
