# 2026-11-08 검색 여러 건을 한 도구 호출로

## 바꾼 것
- `agent/src/semantic_agent/tools/search.py`: `search_laws`·`search_cases`의 입력을 `query`(하나)에서 `queries`(1~6개)로 바꿈. 같은 검색어는 한 번만 부르고, 나머지는 `asyncio.gather`로 동시에 서버 ①을 부른다. 결과는 「### 검색어 N: …」 머리를 붙여 입력 순서대로 이어 붙이고, 하나면 머리 없이 그대로.
- 검색어마다 장부(`Ledger.record_query`)에 적는다. 반대 결론 검색어 확인(reverse_query)은 그대로 동작.
- 조사 하위 에이전트 지시문(`agent/prompts.py`)에 「검색어가 여럿이면 한 호출에 모아 보낸다」 한 줄.
- 서버 ①(Rust)은 바꾸지 않았다. 요청마다 따로 받고, DB 연결 풀이 동시 수를 정한다.

## 왜
- 같은 계열 모델을 쓰는 다른 운영 사례에서 쟁점 1~6개의 검색을 한 호출에 묶어 동시에 돌렸을 때 순차 542초가 최대 172초로 줄었다는 실측이 있다. 모델 왕복(호출마다 문맥 전체를 다시 읽음)이 줄어드는 효과도 있다.

## 시험
- `tests/test_search_batch.py` 2개: 0.2초 걸리는 가짜 검색 3개(중복 1개 포함)가 0.4초 안에 끝나고 순서·중복 제거·장부 기록이 맞음. 하나일 때는 머리 없이 그대로.
- 검색 도구를 쓰는 기존 시험의 인자를 `queries`로 바꿈: test_guards, test_loop, test_real_tools, test_subagents, test_turn_events, test_annex_tool 포함 34개 통과.
- 안 잰 것: 실제 Gemma가 묶어 부르는지, 실제 지연이 얼마나 주는지(Colab 꺼짐).
- 주의: 시험에서 `LEDGER.set`을 쓰면 `reset`으로 되돌려야 다른 시험에 새지 않는다(한 번 새서 반복 차단 시험이 깨졌다).
