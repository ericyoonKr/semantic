# 2026-11-08 요건 판단 질문은 코드가 judge를 부름

## 왜
- 실제 Gemma 4(26B, vLLM 0.33)로 「올린 문서의 사고에 대해 구청에 국가배상책임이 성립하나?」를 돌렸더니 judge를 부르지 않고 조사 결과만으로 「인정될 가능성이 높습니다」라고 결론을 썼다(설계서 원칙 1 위반). 55초, 모델 호출 29회, 판례 검색 503 32회.
- 프롬프트 지시를 더해도 처음 두 호출은 할 일 목록·파일 읽기를 먼저 불렀고, 도구 지정(tool_choice: judge 지정, required)은 이 vLLM·gemma4 파서가 따르지 않았다(직접 요청 2회 모두 도구 없이 글로 결론).

## 바꾼 것
- `agent/src/semantic_agent/agent/judge_route.py`(새 파일), `agent/build.py`: 주 에이전트의 모델 호출 앞에서, 이번 질문이 요건 판단 꼴이고(술어 「성립·해당·충족·인정되·지났·도과·청구할 수 있·받을 수 있…」와 묻는 꼴) 판정 카탈로그의 청구 이름(claim_type에서 `CLAIM_`을 뗀 말, 예 「국가배상」)이 정확히 하나 들어 있으면, 이번 질문에서 judge 결과가 아직 없는 동안에는 모델을 부르지 않고 `judge(claim_type, node_id=claim_type)` 호출을 코드가 만든다. judge 결과가 오면 그 뒤는 모델이 평소처럼 쓴다.
- 감사 기록에 `judge_route`(claim)를 남긴다.

## 잰 것
- 판별 규칙: 직접 만든 질문 40개(국가배상 판단 16, 아님 24; 저장소 밖 `private/eval/judge_route_questions.tsv`)에서 맞게 고름 15, 놓침 1(「구청에 손해배상 청구할 수 있나?」 — 청구 이름이 없음), 잘못 고름 0. 표본을 내가 만들었으므로 실제 사용자 질문 분포의 정확도는 아직 모른다.
- 실제 Gemma로 같은 질문: 55.1초 → 29.2초(첫 답 글 50.2초 → 26.2초), 에이전트 쪽 모델 호출 29회 → 1회, judge 1회, 판례 검색 0회, VerdictReady·NeededFacts 사건이 옴.
- 시험: `tests/test_judge_route.py` 2개, 에이전트 시험 전체 66개 통과.

## 남은 문제(이번에 고치지 않음)
- 판정 결과가 「결론 유보 / 입증책임 적용 시 불성립」이고, 문서에 「구청 도로관리과 담당 공무원」이 적혀 있는데도 가해자 신분을 묻는다. 리프 판정(서버 ①, Gemma)이 문서에서 사실을 찾지 못한 까닭은 아직 보지 않았다.
- 답 글에 `<자료 출처="요건 판단">` 꼬리표가 그대로 섞여 나왔다.
- 청구 이름이 질문에 없으면(놓침 1) 강제하지 않고 프롬프트에 맡긴다.
