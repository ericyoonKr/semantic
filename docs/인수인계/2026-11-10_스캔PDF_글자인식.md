# 스캔한 PDF 글자 인식(PaddleOCR, ONNX) (2026-11-10)

## 사용자 결정

- 스캔한 처분서를 받기 위해 글자 인식을 넣는다. PaddleOCR 모델을 ONNX로 돌린다.
- 모델 파일을 내려받는 것은 사용자가 허락했다. 대상은 한국어 인식 모델, 사전, v5 검출 모델, ONNX Runtime 실행 라이브러리다.

## 바꾼 것

- parsers
  - `src/ocr.rs`, `src/ocr/boxes.rs`(새 파일)
    - 쪽을 300dpi로 그린 뒤 검출 모델로 글자 영역을 찾는다.
      - 긴 변을 1280으로 줄이고 32의 배수로 맞춘다.
      - 확률 0.3 이상인 영역을 연결 요소로 묶는다.
      - 평균 0.6 이상인 영역만 남기고, 1.5배 넓힌다.
    - 영역마다 높이 48로 맞춰 인식 모델을 돌리고, CTC로 글자를 고른다. 사전 뒤에 공백 한 칸을 둔다.
    - 줄 점수가 0.5 아래면 버린다.
    - 모델 폴더(`OCR_DIR`)에는 `det.onnx`, `rec.onnx`, `dict.txt`를 둔다.
  - `PdfReader::with_ocr`: 글자가 없는 쪽만 글자 인식으로 읽는다.
    - 읽은 줄의 사각형을 글자 수만큼 나눠 글자 상자로 만들고, 기존 배치 단계(`lay_out`)에 넘긴다.
    - 그런 쪽은 새 경고 `PagesRecognized`로 표시한다.
    - 글자 인식이 실패하거나 아무것도 읽지 못하면, 예전처럼 「추출 불가」 쪽으로 둔다.
- docmodel: 경고 종류 `PagesRecognized { from, to }`를 더했다.
- server
  - 설정 `OCR_DIR`(없으면 끔)과 `OCR_THREADS`(기본 8)를 더했다.
  - PDF 작업 스레드가 시작할 때 모델을 올린다. 모델이 없으면 글자 인식 없이 계속한다.
  - 경고 문구: 「글자 인식으로 읽음: pN–pM — 인쇄된 글자와 다를 수 있음」
- 시험: `tests/ocr_samples.rs`. 모두 `#[ignore]`이며, 환경변수로 저장소 밖 경로를 받는다.
  - 글자 PDF를 200dpi 스캔본으로 바꾸기
  - 정한 글을 글꼴로 써서 스캔본 만들기
  - 정확도·시간 재기

## 이어서 바꾼 것 (같은 날 저녁)

### 모듈 나눔과 에러 처리

- `ocr.rs`: 적재, 쪽 읽기, 줄 읽기, 추적(`trace_page`)
- `raster.rs`: 쪽 그림. `Crop`(자를 영역 + 흰 여백)을 입력 텐서로 바꾼다.
- `det.rs` + `boxes.rs`: 검출과 영역 고르기
- `components.rs`: 연결 요소 찾기. 검출 후처리와 위첨자 분리가 함께 쓴다.
- `rec.rs` + `ctc.rs`: 줄 인식과 해독
- `split.rs`: 위첨자 분리
- `fix.rs`: 금액 쉼표 보정
- `error.rs`: 글자 인식 오류 형식
  - 오류는 단계(검출·인식), 무엇이 실패했는지(모델 파일·환경·세션·그림·입력·추론·출력 모양·잠금), 원인 문구를 담는다.
  - 다른 모듈은 이 파일의 변환 함수만 부른다.
  - 기록도 이 파일의 함수가 남긴다.
    - 적재 실패: error, 모델 폴더와 함께
    - 쪽 실패: warn, 쪽 번호와 함께
    - 읽은 글자가 없는 쪽: info
  - PDF 읽기는 글자 인식이 실패한 쪽을 쪽 번호와 원인과 함께 기록하고, 「추출 불가」로 둔다. 예전에는 조용히 넘겼다.
  - 파서 오류에 `Ocr(OcrError)`를 더했고, 서버는 이것을 500으로 돌려준다.
- 추적: 줄마다 영역, 잘린 구간(본문·위첨자), 구간마다 읽은 글자를 돌려준다. 실제 읽기와 같은 함수를 거친다. 시험 `trace_ocr_page`가 이것을 출력하고, 구간을 색 상자로 그린 그림을 저장한다.

### 위첨자 분리 (`OcrOptions::split_superscripts`, 기본 켬)

- 큰 글자(상위 20% 높이의 75% 이상)로 줄의 윗선·아랫선을 기울기까지 맞춰 구한다. 두 선은 맞춘 선에서 20%·80% 분위만큼 옮긴다.
  - 조각을 한 글자로 묶는 조건: 위아래로 쌓이고 가로로 30% 이상 겹치거나, 가로로 70% 이상 겹친다.
  - 줄 영역의 위·아래 경계에 닿은 조각은 이웃 줄의 것으로 보고 뺀다.
- 세로 열마다 기준선 둘레(윗선 위로 본문 높이의 50%, 아랫선 아래로 25%)의 잉크를 본다.
  - 잉크의 바닥이 윗선에서 본문 높이의 60% 안에 있고 높이가 본문 높이의 65% 이하인 열은 「위첨자 열」이다.
  - 아래까지 내려오는 열은 「본문 열」이다.
- 위첨자 열이 이어진 구간이 본문 높이의 1.5배 이상이면 위첨자 구간이다. 글자 사이의 빈 열은 본문 높이의 절반까지 허용한다.
- 위첨자 구간은 글자에 딱 맞게 잘라 둘레에 흰 여백(구간 높이의 80%)을 덧대고, 가로로 1.5배 늘려 읽는다.
- 읽은 위첨자에 숫자가 2개 미만이면, 자른 것을 버리고 그 줄을 통째로 다시 읽는다.
- 실패한 방식과 그 이유(추적으로 확인)
  - 조각 단위 판단: 한글의 위쪽 자모(「또」의 ㄸ)를 위첨자로 봄
  - 짧은 줄에서 중앙값 높이: 위첨자가 많으면 중앙값이 위첨자 높이가 됨
  - 이웃 글자 획을 포함한 여백: 「1」·「|」로 읽힘
  - 글자 상자 밖 지우기: 바탕체의 가는 획을 지움
  - 조각 단위로는 「의」와 위첨자 「2」가 픽셀로 이어져 「2」를 놓쳤다. 세로 열 방식으로 바꿔 해결했다.

### 금액 쉼표 보정 (처음 판, 아래 「글자 바로잡기」로 바뀜)

- 「1~3자리 + (마침표 또는 쉼표 + 3자리)가 2번 이상 + 원」일 때만 마침표를 쉼표로 바꾼다. 예: 「24.609.019원」→「24,609,019원」
- 3자리 묶음이 하나뿐이면(「366.000원」) 소수 금액(「리터당 123.456원」)과 구별할 수 없어 바꾸지 않는다. 묶음 하나에서도 바꾸던 처음 판은 바꾸면 안 되는 표본의 소수 금액 40개를 모두 잘못 바꿨다.

## 한계 고치기 (같은 날 밤)

### 글자 바로잡기 (`OcrOptions::fix_text`, 기본 켬, `fix.rs`)

- 금액: 3자리 묶음이 하나뿐이어도 마침표를 쉼표로 바꾼다. 다만 앞자리가 0이거나(「0.027원」) 「원」 바로 뒤에 「/」가 오면(「20.605원/㎏」) 소수로 둔다.
  - 근거: 현행 조문의 묶음 하나짜리 금액 730건(쉼표 724, 소수 6)에 이 규칙을 적용했다.
    - 소수 6건은 모두 그대로 남았다. 잘못 바꾼 것은 0건이다.
    - 쉼표 724건 중 703건은 쉼표로 돌아왔다.
    - 「5,000원/월」 같은 21건은 바꾸지 않고 둔다.
- 사건부호: 「숫자 + 현 + 마·바·가·나·라·사·아 + 숫자」이면 「헌」으로 바로잡는다.
- 낫표: 「[」 또는 「「」로 열고 「]」 또는 「」」로 닫은 안쪽이 법·법률·령·규칙·조례·규정·고시로 끝나면 「「 … 」」로 바꾼다. 별표·별지·서식으로 시작하면 그대로 둔다.

### 본문 인식 가로 배율 1.2 (`REC_WIDTH_SCALE`)

- 같은 숫자가 이어질 때 하나로 줄어드는 오류를 줄이려고 1.0에서 1.2로 바꿨다(1.5는 열화 표본을 나쁘게 했다).

### 짧은 각주 번호

- 위첨자 후보 폭을 본문 높이의 0.5배까지 낮추고, 각주 꼴(「12)」)을 받아들이는 판도 재 보았다.
  - 본문 숫자 「7」의 윗부분 열이 위첨자로 잘려 「3,967원」을 「3,96775원」으로 읽었다. 그래서 되돌렸다.
  - 각주 번호 표본(120개)은 자르지 않고도 113/120을 이미 맞혔다. 앞서 적은 「짧은 각주 번호는 못 읽음」은 재 보지 않고 쓴 것이었다.

## 알려진 한계

- 열화 표본에 숫자 6개가 남는다.
  - 흐린 낫표가 인식에서 아예 사라짐(4개). 글자가 없으니 낫표 규칙으로 되살릴 수 없다. 예: 「행정기본법」→ 행정기본법
  - 글자 빠짐(2개): 「2025두137425」→「2025137425」, 「95,462,883원」→「95,46,883원」
- 「(「정부조직법」」처럼 여는 낫표가 괄호와 붙어 있으면 인식에서 여는 낫표가 사라진다.
- 열화는 직접 만든 것이다. 실제 스캐너로 찍은 문서로는 아직 재지 않았다. 실제 스캔본 표본이 있어야 잴 수 있다.
