# 스캔한 PDF 글자 인식(PaddleOCR, ONNX) (2026-11-10)

## 사용자 결정

- 스캔한 처분서를 받기 위해 글자 인식을 넣는다. PaddleOCR 모델을 ONNX로 돌린다.
- 모델 파일을 내려받는 것은 사용자가 허락했다. 대상은 한국어 인식 모델, 사전, v5 검출 모델, ONNX Runtime 실행 라이브러리다.

## 바꾼 것

- parsers
  - `src/ocr.rs`, `src/ocr/boxes.rs`(새 파일)
    - 쪽을 300dpi로 그린 뒤 검출 모델로 글자 영역을 찾는다.
      - 긴 변을 1280으로 줄이고 32의 배수로 맞춘다.
      - 확률 0.3 이상인 영역을 연결 요소로 묶는다.
      - 평균 0.6 이상인 영역만 남기고, 1.5배 넓힌다.
    - 영역마다 높이 48로 맞춰 인식 모델을 돌리고, CTC로 글자를 고른다. 사전 뒤에 공백 한 칸을 둔다.
    - 줄 점수가 0.5 아래면 버린다.
    - 모델 폴더(`OCR_DIR`)에는 `det.onnx`, `rec.onnx`, `dict.txt`를 둔다.
  - `PdfReader::with_ocr`: 글자가 없는 쪽만 글자 인식으로 읽는다.
    - 읽은 줄의 사각형을 글자 수만큼 나눠 글자 상자로 만들고, 기존 배치 단계(`lay_out`)에 넘긴다.
    - 그런 쪽은 새 경고 `PagesRecognized`로 표시한다.
    - 글자 인식이 실패하거나 아무것도 읽지 못하면, 예전처럼 「추출 불가」 쪽으로 둔다.
- docmodel: 경고 종류 `PagesRecognized { from, to }`를 더했다.
- server
  - 설정 `OCR_DIR`(없으면 끔)과 `OCR_THREADS`(기본 8)를 더했다.
  - PDF 작업 스레드가 시작할 때 모델을 올린다. 모델이 없으면 글자 인식 없이 계속한다.
  - 경고 문구: 「글자 인식으로 읽음: pN–pM — 인쇄된 글자와 다를 수 있음」
- 시험: `tests/ocr_samples.rs`. 모두 `#[ignore]`이며, 환경변수로 저장소 밖 경로를 받는다.
  - 글자 PDF를 200dpi 스캔본으로 바꾸기
  - 정한 글을 글꼴로 써서 스캔본 만들기
  - 정확도·시간 재기
  - 쪽 윗부분을 그림으로 저장하기

## 잰 것

- 성공 기준: 정답이 깨끗한 표본에서 글자 오류율 2% 이하, 숫자 표기 정확도 99% 이상, 쪽당 10초 이하.
- 깨끗한 표본: 조문 350줄과 숫자가 많은 줄 160줄을 맑은 고딕·바탕으로 써서 200dpi 스캔본으로 만든 13쪽, 13,093자.

  - 숫자 표기(사건번호·날짜·금액·조문 번호) 339/339
  - 쪽당 5.9초

- 실제 법학 PDF 20쪽(글자 PDF를 200dpi 스캔본으로 바꿈)
  - 순서와 관계없이 센 재현율·정밀도(16스레드)
    - 1920: 98.6%·94.9%
    - 1280: 98.6%·95.0%
    - 960: 98.1%·94.9%
  - 이 표본은 원본 PDF의 글자 순서가 깨져 있거나 그림 속 글자가 정답에 빠져 있다. 그래서 순서대로의 오류율은 정답으로 쓰지 않았다.
  - 그래서 기본값을 1280으로 했다. 960에서는 재현율이 0.5%p 떨어진다.
- 지어낸 처분서 스캔본(바탕 글꼴): 글자 오류율 0.5%, 숫자 8/8, 4.4초
  - 띄어쓰기가 많이 빠지지만, 인용문 대조(`locate_quote`)는 공백 차이를 무시한다.
- 게이트웨이를 거쳐 스캔본 처분서를 올렸다.
  - 올리기는 5.9초 걸렸다.
  - 판정 뒤 답 쓰기는 생성 모델 서버(Colab)가 꺼져 있어 실패했다. 리프 판정 결과도 모델이 없어 믿을 수 없다.
- 시험: parsers 라이브러리 32개, docmodel 5개, server 라이브러리 23개 통과

## 알려진 한계

- 본문 줄 끝의 아주 작은 위첨자(약 5pt 각주 번호)는 줄과 함께 높이 48로 줄어들어 숫자가 빠진다. 예: 「2019다213344」를 「2019다2334」로 읽음. 위첨자만 따로 잘라 읽는 개선은 하지 않았다.
- 낫표 「」가 [ ] 등으로 바뀌는 문장 부호 오류가 있다.
- 실제 스캐너로 찍은 문서(기울어짐, 얼룩)로는 아직 재지 않았다.
- clippy는 이번 변경에 대해 아직 돌리지 않았다.
