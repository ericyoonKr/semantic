# 2026-11-13 화면: 굵은 글씨·목록, 근거 원문 표시, 생각 구간 숨기기, 대화 이름 바꾸기

## 바꾼 것
- **답 글 그리기**(`web/src/features/chat/rich.ts`, `AnswerText.tsx`)
  - `**…**`는 굵게 그린다. 짝이 맞지 않는 `**`는 그대로 둔다.
  - `* `·`- `·`• `로 시작하는 줄을 이어서 목록으로 그린다. 나머지 줄은 문단이다.
  - HTML을 끼워 넣지 않고 React 요소로만 그린다.
- **근거 원문 표시**
  - **에이전트**(`api/answer_gate.py`, `api/sources.py`, `ledger.py`)
    - 인용 검사(`SentenceGate`)를 통과한 문장이 가리키는 장부 항목(`[근거 n]`, 「법령명 제N조」, 사건번호)을 기록한다.
    - 답이 끝나면 `Sources` 이벤트로 항목마다 이름·시행일·원문·짚은 구간을 보낸다.
    - 짚는 방법
      - 법령은 문장에 항이 적혀 있으면 그 항(①…)의 구간을 짚는다.
      - 항이 없으면 원문 줄 가운데 그 문장과 두 글자 조각이 가장 많이 겹치는 줄을 짚는다(4조각 이상일 때만).
      - 판례는 짚은 구간 앞뒤 700자만 보낸다.
  - **게이트웨이**(`filter.rs`)
    - `Sources`를 화면으로 넘긴다.
    - 종류가 law·case가 아닌 항목은 버린다.
    - 원문은 2만 자까지만 넘긴다.
    - 원문 길이를 벗어나는 구간은 버린다.
  - **화면**
    - 답 속 조문·판례 이름(시행일 표시 포함)과 답 아래 「근거」 칩을 누르면 원문이 열리고, 짚은 구간에 형광 표시를 한다.
    - 근거는 지금 화면의 턴에만 있다. 대화 기록(`/history`)에는 저장하지 않는다.
- **생각 구간 숨기기**
  - Gemma 4는 생각을 `<|channel>thought\n…<channel|>`로 쓴다. 온프레미스 모델 폴더의 `chat_template.jinja`와 `tokenizer_config.json`에서 확인했다.
  - **에이전트**(`api/thought.py` `ThoughtFilter`): 조각으로 나뉘어 와도 이 구간과 `<think>…</think>`를 인용 검사 전에 지운다. 닫히지 않은 구간은 버리고, 짝 없는 닫는 표시도 지운다.
  - **게이트웨이**: 기본 숨김 구간(`DEFAULT_HIDDEN_SPANS`)에 `<|channel>|<channel|>`을 더했다. 표시 안에 `|`가 들어 있어 설정 읽기(`parse_spans`)가 `>|<`를 먼저 구분자로 본다.
- **대화 이름 바꾸기**
  - 게이트웨이: `PATCH /session/{id}` `{"title": …}`. 본인 대화만 바꿀 수 있다. 공백을 하나로 줄이고, 빈 이름·80자 초과·제어 문자는 400으로 거절한다.
  - 목록(`/api/sessions`)에 `title`을 싣는다.
  - 화면: 대화 목록의 「이름」 단추를 누르면 그 자리에서 고친다. Enter는 저장, Esc는 취소, 칸을 벗어나면 저장한다.

## 남은 것

- 새로고침하면 쓰던 답이 끊김: 브라우저 연결이 끊기면 게이트웨이와 에이전트도 그 질문을 멈춘다.

## 추가(같은 날 오후): 새로고침해도 답이 이어짐, 고른 대화 기억
- **에이전트**(`api/runlog.py`, `api/app.py`, `api/sessions.py`)
  - 질문 실행을 HTTP 연결에서 뗐다. 이벤트는 대화별 `RunLog`에 쌓이고, 응답은 그 기록을 따라 읽는다.
  - 연결이 끊겨도 실행은 계속된다. 실행 작업은 `AppState.background`가 붙잡아 둔다.
  - `GET /session/{id}/live`: 진행 중인 실행이 있으면 `Resume {question}`을 먼저 보내고, 처음부터 끝까지 다시 흘린다. 없으면 204.
- **게이트웨이**: `GET /session/{id}/live`가 본인 대화인지 확인한 뒤 에이전트로 넘긴다. 같은 필터를 거친다.
  - 이 경로에서는 사용량·감사 기록을 다시 적지 않는다. 같은 실행이 두 번 세어지지 않게 하려는 것이다.
  - 따라서 처음 연결이 끊긴 실행의 사용량은 적히지 않는다.
- **화면**
  - 대화를 열면 기록을 읽은 뒤 `live`에 붙는다. 진행 중이면 그 질문으로 턴을 만들어 이어서 보여 준다.
  - 기록 끝에 같은 질문이 이미 있으면 한 번만 보이게 뺀다.
  - 고른 대화 ID를 브라우저 저장소(`semantic.selected-session`)에 두어, 새로고침 뒤에도 같은 대화가 열린다. 목록에 없는 ID면 버린다.
- **확인**
  - 실제 에이전트에 질문을 보내고 4초 만에 연결을 끊은 뒤, 2초 뒤 `live`에 다시 붙었다.
  - 답이 끝까지 왔다(글 289자, 근거·사용량·끝 이벤트 포함, 생각 표시 없음). 끝난 뒤 `live`는 204였다.
- **시험**: 에이전트 167, 게이트웨이 단위 30·저장소 DB 6, 화면 58 통과. clippy 0.

## 추가(같은 날 오후 3시 이후)
- **근거를 DB와 대조**(`agent/api/verify.py`)
  - 장부 항목에 우리 DB ID를 싣는다(법령 `law_id`·조문 판본 ID, 판례 `decision_id`).
  - 답이 끝나면 근거마다 검색 서버에 그 ID로 다시 조회한다.
    - 법령: 판본 ID와 원문이 같아야 한다.
    - 판례: 사건번호가 같아야 한다.
  - 결과를 `verified`·`verify_note`(DB에서 찾지 못함 / DB 원문과 다름 / ID 없음)로 보낸다. 화면은 칩에 확인 표시를 붙이고, 원문 창에 「DB 대조 확인 · ID …」 또는 실패 이유를 보인다.
- **기록에 근거 남기기**(`agent/api/answers.py`)
  - 답이 끝나면 화면에 보낸 답 글과 근거를 저장소(`answers/{user}/{session}`, 키는 답 메시지 ID)에 둔다.
  - `/history`는 저장된 것이 있으면 그 글과 근거를 돌려준다. 그래서 새로고침 뒤에도 근거 칩이 남고, 「[근거 N]」 표시가 그대로 보이지 않는다.
- **근거 장부를 대화 안에서 이어 씀**
  - 대화별 장부를 세션 칸에 두고 질문마다 이어 쓴다. 앞 질문에서 읽은 자료는 다음 질문에서도 같은 근거 번호다.
  - 장부는 저장소(`ledger/{user}/{session}`)에도 남겨, 에이전트를 다시 띄워도 불러온다. Postgres가 받지 못하는 널 문자는 저장할 때 뺀다.
  - 대화를 지우면 답·장부도 지운다.
- **지시문**
  - 판례 번호·조문을 물으면 이미 받은 근거에서 먼저 고르고, 없을 때만 검색을 맡긴다.
  - 검색해도 없으면 「우리 법령·판례 자료에서 찾지 못했다」고 쓴다.
  - 이모티콘을 쓰지 않는다. 이모티콘은 답 글에서 기계로도 지운다(`api/emoji.py`). ①·※·→ 같은 표시는 남긴다.
- **화면**: 마크다운 표(머리 줄, 행 사이 빈 줄 허용), 제목 줄, 구분선을 그린다.
- **실제 확인**
  - 「국가배상법 제2조의 요건」을 물었더니, 근거 1개가 DB 대조에서 확인되었다.
  - 이어서 「방금 근거로 든 조문 번호만 다시」를 물었더니, 도구를 부르지 않고 1초 만에 같은 근거로 답했다. 대조도 확인되었다.
  - 장부·답 저장 실패 기록은 0건이었다.
- **남은 것**
  - 조사 하위 에이전트(Gemma 26B)가 판례를 검색만 하고 읽지 않아, 판례를 근거로 들지 못하는 경우가 있다. 한 시험에서 판례 검색 4번, 판례 읽기 0번이었다.
  - 이것은 아직 고치지 않았다.

## 추가: 공문 초안 허용, 올린 파일 원문 보기
- **범위**
  - 본인 명의의 간단한 공문·협조 요청·질의서·회신 초안을 답 안에 글로 쓴다. 초안 속 법령·판례도 근거 규칙을 지키고, 모르는 사실은 「[확인 필요: …]」로 둔다.
  - 남이 발급하는 증서·증명서·확인서·인증서를 고쳐 쓰거나 새로 만드는 요청은 가드(`DOCUMENT_WORDS`)에서 막는다.
  - 가드 표본(허용 4·거절 4)이 모두 맞았다.
  - 실제 모델로 해 보니 공문 초안은 9초 만에 썼고, 증서를 고쳐 써 달라는 요청은 바로 거절했다.
- **올린 파일 원문 보기**
  - 에이전트: `GET /session/{id}/files`(목록), `GET /session/{id}/files/{file_id}`(추출한 글). 글은 대화 상태의 `/uploads/{file_id}.md`에서 읽는다. 파일 ID는 영숫자·`-`·`_`만 받는다.
  - 게이트웨이: 같은 두 경로. 본인 대화인지 확인하고, 파일 ID를 거른다.
  - 화면: 「올린 파일」 창에서 파일마다 「원문 보기」를 누르면 추출한 글을 쪽 단위로 보여 준다.
  - 원본 바이트(PDF 화면 그대로 보기)는 지금 어디에도 저장하지 않아 보여 줄 수 없다.
  - 확인: 작은 DOCX를 실제로 올려 목록과 글이 나오는 것을 봤다. 없는 파일 ID는 404였다.
