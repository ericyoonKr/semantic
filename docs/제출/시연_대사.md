# 시연 영상 대사 (Legal AI Agent using Semantic RAG)

영상 순서: 02 파일 앞부분(장면 0~2) → 03 파일(장면 3~4) → 02 파일 뒷부분(장면 6-A·6-B) → 마무리. 한 장면에 대사 두세 문장, 화면이 답을 기다리는 동안 읽는다.

## 장면 0 — 소개 (빈 대화 화면, 약 90초)
안녕하세요. 단국대학교 소프트웨어학과 32227546 윤치호, 팀 「특이점이 온다」입니다. 작품 이름은 「의미론적 RAG를 이용한 법률 인공지능 에이전트」입니다.

**왜 만들었나.** 큰 언어 모델에 법률을 물으면 그럴듯한 법령명과 조문 번호, 사건번호를 지어냅니다. 실제와 다른 「제N조」를 들고, 없는 판례를 인용하고, 자료에 없는 조례를 「없다」고 단정합니다. 인용이 그럴듯할수록 사용자는 확인하지 않기 때문에, 법률 상담 보조에서 이것이 가장 위험한 실패입니다.
흔히 쓰는 검색 증강 생성, RAG는 이 문제를 절반만 풉니다. 질문으로 한 번 검색해 몇 문단을 붙이고 모델이 답을 쓰는 방식은, 검색이 빗나가면 모델이 다시 기억으로 쓰고, 조문 전체를 붙여서 어느 항·호가 근거인지 흐려지고, 시행일이 다른 판본을 섞고, 모델이 쓴 인용이 실제로 읽은 것과 맞는지 아무도 확인하지 않습니다.

**무엇이 다른가.** 이 작품은 네 가지를 지킵니다.
첫째, 법령·판례·조례·학칙은 실제로 읽은 것만 인용합니다. 답은 문장 단위로 흘러나오고, 문장마다 Rust로 짠 인용 관문이 「법령명 제N조」와 사건번호를 읽은 근거와 대조합니다. 안 맞는 문장은 화면에 나가지 않습니다.
둘째, 조문 전체가 아니라 맞는 단위를 찾습니다. 글자 검색과 벡터 검색을 순위 역수 합으로 합치고, 조문에서 항·호·목으로 내려가 질문 날짜에 효력 있던 판본만 돌려줍니다. 조문 판본, 항·호·목 단위, 별표의 표와 행, 판례의 판단 조각을 따로 임베딩해 둔 덕분입니다. 법령·행정규칙 3만여 건, 서울시와 자치구의 조례·규칙 만 오천여 건, 대학 학칙과 판례까지 조문 단위 430만 개가 들어 있습니다.
셋째, 다음에 무엇을 할지를 모델이 정하지 않습니다. 서버의 함수가 질문과 앞선 대화, 이미 읽은 근거를 보고 조사를 먼저 시키고, 조사 하위 에이전트가 검색과 읽기를 반복한 뒤 읽은 것만 근거 번호를 받습니다. 그래서 「무슨 법?」 같은 두 낱말 후속 질문도 기억이 아니라 조사로 갑니다.
넷째, 요건 판단은 모델이 결론을 내지 않습니다. 요건 나무의 잎 하나씩만 모델이 사실과 근거로 판정하고, 조합과 기간 계산은 논리 엔진 Z3와 Rust 코드가 합니다. 인용한 원문이 문서에 없으면 그 잎은 「알 수 없음」으로 남습니다.

**지식그래프와 팀 이름.** 개념 연결망, 요건 나무, 절차 흐름, 조직 연혁 등 열여섯 개 지식그래프를 읽기 전용으로 두고, 질문의 낱말로 그래프에서 쟁점과 요건을 먼저 찾은 뒤 조문을 읽습니다. 이 그래프는 사람이 그린 것이 아니라 인공지능이 법령 원문을 읽어 만들었습니다. 사람 팀원은 한 명이지만 팀 이름이 「특이점이 온다」인 이유입니다.

**어디서 돌아가나.** 생성 모델 Gemma 4 26B와 임베딩 모델 bge-m3는 공개 가중치라 외부 API 없이 자체 GPU 한 대에서 vLLM으로 띄웁니다. 데이터베이스와 색인도 모두 자체 설치형이어서, 기관 안에 온프레미스로 두면 조문·판례·올린 문서·대화가 밖으로 나가지 않습니다. 밖에 열리는 서버는 Rust 창구 하나뿐이고, 판단 논리는 전부 Rust, 파이썬은 에이전트 루프를 잇는 역할만 합니다.

지금부터 실제 화면으로 보여 드리겠습니다.

(짧게 읽을 때) 안녕하세요. 팀 「특이점이 온다」의 졸업작품, 「의미론적 RAG를 이용한 법률 인공지능 에이전트」입니다. 이 챗봇은 법령·판례·조례·학칙을 실제로 읽은 것만 인용해 답합니다. 기억으로 쓴 법령과 판례는 문장째 걸러냅니다. 모델은 공개 가중치인 Gemma 4와 bge-m3라서 외부 API 없이 온프레미스로 돌아갑니다.

## 장면 1 — 법령 질문과 근거 칩
질문은 「클럽에서 마약 투약을 방치한 업소를 제재할 수 있는 근거가 뭐야?」입니다.
(답을 기다리며) 질문이 들어오면 모델이 바로 답하지 않습니다. 서버 함수가 먼저 조사를 시키고, 조사 에이전트가 뜻과 글자를 함께 쓰는 하이브리드 검색으로 조문을 찾아 읽습니다.
(답이 나오면) 문장마다 조문이 달려 있고, 아래 칩은 이번 질문에서 실제로 읽은 조문만 붙습니다. 「DB 대조 확인」 표시는 그 조문이 자료에 그대로 있다는 뜻입니다.
(칩을 누르며) 칩을 누르면 조문 전문이 열리고 답에 쓴 부분이 노랗게 표시됩니다. 읽지 않은 법령을 인용한 문장은 관문이 내보내지 않습니다.

## 장면 2 — 후속 질문과 조례
이어서 「무슨 법?」이라고만 물어보겠습니다.
(답이 나오면) 두 낱말짜리 질문도 앞 질문과 직전 답을 붙여 조사로 갑니다. 다음에 무엇을 할지는 모델이 아니라 서버 함수가 정하기 때문입니다.
이번에는 조례를 물어보겠습니다. 「서울특별시 청년 기본 조례 제3조에서 청년의 정의가 어떻게 돼?」
(답이 나오면) 자치법규도 같은 방식으로 읽습니다. 칩에 「자치법규」라고 종류가 붙고, 조문 원문이 그대로 열립니다. 서울시와 자치구의 조례·규칙 만 오천여 건이 들어 있습니다.

## 장면 3 — 학칙
새 대화에서 「단국대 학칙에서 휴학은 어떻게 규정돼 있어?」라고 묻겠습니다.
(답이 나오면) 칩에 「기관 규정」이라고 붙습니다. 법령·행정규칙·조례·학칙을 한 명세로 구분해 다루고, 학칙은 법률이 아니라는 지시가 모델에 붙습니다.
이어서 「고등교육법과는 어떻게 이어져?」
(답이 나오면) 고등교육법 조문과 학칙 조문을 짝지어 답합니다. 상위 법령과 기관 규정을 조문 단위로 이어 주는 겁니다.

## 장면 4 — 문서 올리고 판단
이번에는 실제 감사 처분요구서를 올려 보겠습니다. 강원도 감사위원회의 공직감찰 처분요구서입니다.
(원문 보기를 열며) 올린 문서는 쪽 단위로 원문을 볼 수 있습니다.
질문은 「이 처분요구의 훈계·주의가 지방공무원법상 징계야? 다투어 볼 수 있어?」입니다.
(답이 나오면) 첫 문장에 결론이 나옵니다. 「아니오」, 훈계와 주의는 지방공무원법 제70조의 징계 종류에 없다는 겁니다. 문서에서 가져온 사실에는 「파일명 · 쪽」이 붙고, 법령에는 조문이 붙습니다.
(쪽 인용을 누르며) 쪽 인용을 누르면 그 쪽이 옆에 열리고, (칩을 누르며) 조문 칩을 누르면 제70조 원문에서 답에 쓴 부분이 표시됩니다.

## 장면 6-A — 스캔본 처분서와 절차
스캔한 처분서 PDF를 올리겠습니다. 글자가 없는 스캔본은 글자 인식을 거쳐 같은 방식으로 다룹니다.
질문은 「이 처분 절차에 문제 없어? 사전통지와 의견제출 기회는 줬어?」입니다.
(답이 나오면) 행정절차법의 사전통지·의견제출 요건과 판례를 들어 절차 하자를 짚어 줍니다.

## 장면 6-B — 요건별 판단
같은 처분서로 「이 영업정지 처분이 위법한지 요건별로 판단해 줘」라고 묻겠습니다.
(답이 나오면) 처분의 근거 조문, 절차, 재량 기준을 요건별로 나눠 판단하고 요건마다 근거를 답니다. 인용한 원문이 문서에 없으면 그 요건은 「알 수 없음」으로 두고 지어내지 않습니다.

## 마무리
정리하면, 이 시스템은 세 가지가 다릅니다.
첫째, 법령·판례·조례·학칙을 실제로 읽은 것만 인용하고, 읽지 않은 인용은 문장째 걸러냅니다.
둘째, 다음 단계를 모델이 아니라 서버 함수가 정하고, 요건 판단은 잎 하나씩 모델이 보고 조합은 논리 엔진이 합니다.
셋째, 지식그래프 열여섯 개를 소비해 쟁점과 요건을 먼저 찾고, 공개 가중치 모델로 온프레미스에서 돌아갑니다.
감사합니다.
