# 구현 계획서

작성일: 2026-11-07. `IMPLEMENTATION_ORDER.md`(2026-09-29)를 옮기고 2026-11-07 결정을 반영했다.
설계는 `docs/설계서.md`, 파일마다 할 일은 `docs/구현지시서.md`. 단계 번호는 이 문서 안에서만 쓰는 순번이다.

## 순서를 정한 기준

1. **소비 규격을 먼저 정한다.** 도구의 입력·출력(설계서 §13.3)을 먼저 고정하고, 가짜 도구로 에이전트 루프를 시험한 뒤 실제 구현을 붙인다.
2. **바닥 타입을 먼저 만든다.** 다른 crate가 쓰는 타입(docmodel, llm)이 앞에 온다.
3. **단계가 끝날 때마다 채팅에서 직접 써 볼 수 있는 기능이 하나씩 늘어나게 한다.**
4. **판정 장치는 정확도를 잰 뒤에 저장 경로에 붙인다.** 맞는 표본(오탐)과 틀린 표본(누락)을 함께 센다.
5. **단계를 시작할 때 무엇을 재서 무엇이 나오면 성공인지 한 줄로 먼저 적는다.**
6. 이 저장소는 소비 쪽만 만든다. 법령·판례 DB와 지식그래프 묶음은 생산 계층이 넘긴다(설계서 §2.1).
7. **단계마다(작업마다) 작업 인수인계서를 남긴다** — `docs/인수인계/`(형식은 구현지시서 공통 규칙).
8. **주요 단위마다 커밋한다.** 커밋 직전에 올라갈 변경에서 비밀값·데이터 파일·코드 주석·외부 흔적을 세어 0일 때만 커밋한다. 기본 가지에서는 작업 가지를 만들어 커밋한다. 푸시는 따로 정한다.
9. **아직 하지 않은 것**(가드레일·메모리·예산·감사·CI 등)은 구현지시서 「아직 하지 않은 것」 A~R에 단계별로 있다. 그 단계에서 함께 한다.

## 5단계 — 지식그래프 읽기

| 순서 | 파일 | 내용 |
|---|---|---|
| 1 | `crates/kg/src/*`(새 crate), `Cargo.toml`(다시) | 묶음 검사·SQLite 적재·find·expand·짧은 번호 |
| 2 | `crates/server/src/main.rs`·`routes.rs`(다시) | `/kg/catalog`, `/sessions/{sid}/kg/find`, `/sessions/{sid}/kg/expand` |
| 3 | `agent/semantic_agent/tools.py`·`context.py`(다시) | `kg_find`·`kg_expand`(번호를 그대로 주고받음), 카탈로그 붙이기 |

**성공 기준**
- 받은 헌법 묶음을 적재하면 노드·간선·상태 수가 머리 `counts`와 같다. 일부러 한 줄을 지운 묶음, 해시를 바꾼 묶음은 적재되지 않고 그 묶음만 꺼진다(누락 0, 서버는 계속). 같은 묶음으로 다시 기동하면 적재를 건너뛴다.
- 두 글자 검색어(예: 「기본권」이 아닌 두 글자 개념명)도 찾힌다.
- 계약 밖 관계로 `expand`하면 거부된다. 모델이 짧은 번호로 부른 노드가 원래 ID로 되돌아간다(시험 20건 중 틀림 0).
- 시험은 시험 코드가 만든 가짜 묶음으로 한다. 실제 묶음은 저장소에 넣지 않는다.

**성공 기준**
- 손으로 넣은 리프 조합마다 Z3 결론(성립·불성립·유보)과 unsat_core 노드가 기대값과 모두 맞는다.
- 인용 대조 검사: 원문에 있는 인용(공백·줄바꿈만 다름) 표본을 통과시키는지(오탐), 한 글자라도 바뀐 인용을 막는지(누락).

  사용자가 답하면 그 진술이 들어간 리프만 다시 판정된다(cache_key 변화로 확인). 「인정된다고 보자」는 가정 표시와 함께 다시 판정된다.

| 1 | `crates/gateway/src/main.rs`, `auth.rs` | 기동, 사용자 명령, 로그인 세션, CSRF, 시도 제한 |
| 2 | `proxy.rs`, `filter.rs`, `static_files.rs` | 소유자 확인·④로 넘기기, SSE 거르기, 빌드 파일 제공 |
| 3 | `agent/semantic_agent/app.py`(다시) | 127.0.0.1, 내부 키·`x-user-id` 확인, `history` 줄이기 |

**성공 기준**
- 틀린 비밀번호 5회 → 잠금, 잠금 중 맞는 비밀번호도 거부. 로그인 전후 토큰이 다르다. 로그아웃한 쿠키로는 아무 경로도 안 된다.
- CSRF 토큰 없는 POST는 거부. 다른 사용자의 대화 ID로 부르면 404.
- 프론트로 나간 SSE·응답·오류를 모아, 도구 이름·노드 ID·내부 경로·모델 이름이 0건인지 센다.
- ④·①을 밖 주소로 부르면 연결되지 않는다(127.0.0.1).

## 10단계 — 웹 프론트 (React)

1~9단계 백엔드를 다 짠 뒤 붙인다. `web/`(React + TypeScript, 빌드 도구는 그때 정함). 제출하지 않는다.
⓪의 `/api/auth/*`, `/api/sessions`, `POST /session`, `ask`(SSE), `history`, `upload`, `DELETE /session/{id}`, `DELETE /prefs`만 쓴다.
화면: 대화, 파일 올리기와 업로드 목록·목차, 판정 문장(`VerdictReady`)을 서술과 따로 보이는 칸, 필요한 사실 질문(`NeededFacts`), 강등·추출 불가 경고.
화면에는 백엔드 동작을 드러내지 않는다(설계서 §20).

**성공 기준**: 2~8단계의 채팅 성공 기준을 화면에서 다시 확인한다(판정 문장 원문이 서술과 따로 보이는지, SSE가 끊긴 뒤 새로고침하면 `history`로 다시 그려지는지).
