# 구현 지시서

작성일: 2026-11-07. 파일마다 무엇을 담을지와 지킬 규칙. 설계는 `docs/설계서.md`, 단계와 성공 기준은 `docs/구현계획서.md`.
`IMPLEMENTATION_ORDER.md`의 「파일 순서」와, 코드 파일 머리에 있던 「담을 것」 주석을 이 문서로 옮겼다(코드에는 주석을 남기지 않는다 — 설계서 §2.1).

## 공통 규칙

- **주석 없음**: 코드(Rust·Python·SQL·셸·TOML)에 주석과 문서 주석(`///`, `//!`, docstring)을 남기지 않는다. 설명은 이 문서에만.
- **공개 범위**(설계서 §2.1): 학교에는 `crates/`·`Cargo.toml`·`Cargo.lock`·`LICENSE`만. `crates/` 아래에 `.json`·`.jsonl`·`.sqlite`·`.db`를 두지 않는다.
  시험 표본은 시험 코드 안에서 만든다. 소스 문자열(오류 문구·로그 포함)에 실제 데이터 내용, 생산 계층의 경로·주소·DB 이름, 비밀값을 넣지 않는다.
  다른 프로젝트의 코드·문서를 가져오지 않는다.
- **데이터 경로**: `DATA_DIR`, `KG_DIR` 환경변수. 기본값은 저장소 밖. 저장소 안을 기본값으로 두지 않는다.
- **비밀값**: 환경변수로만. 기본값 자리에 넣지 않는다. 커밋 전 `git diff --cached`를 비밀값·데이터 확장자로 훑는다.
- **오류**: 층별 thiserror enum. 핵심 코드 `unwrap`·`expect`·`panic!` 금지(clippy `unwrap_used`·`expect_used`·`panic` deny — 정규식 상수처럼 컴파일 때 확정되는 것만 허용 목록에). 실패는 Unknown·판정 불가 쪽으로만(설계서 §1.2 원칙 2).
- **동기·비동기 경계**: engine(slices·leaf 제외)·parsers·checks·kg 탐색은 동기 순수 함수, 호출자가 `spawn_blocking` (설계서 §11).
- **검사 장치**: 검사·판정 장치를 저장 경로에 붙이기 전에 맞는 표본(오탐)·틀린 표본(누락)으로 정확도를 재고 숫자를 남긴다.
- **시스템 고려**: 동시성·멀티코어 자원 배분(설계서 §11.1·§11.2), 마감의 겹침·밖에 보이는 오류·요청 ID·종료 절차(§12), 보안(§17), 그 밖의 시스템 문제(§18)를 파일마다 지킨다.
- **작업 인수인계서**: 구현 작업을 하면 끝날 때마다 `docs/인수인계/YYYY-MM-DD_<주제>.md`를 남긴다 — 한 일, 바뀐 파일, 잰 것과 숫자, 안 잰 것, 남은 결정, 다음에 할 일.
  생산 계층·외부 자료·데이터 내용·비밀값이 들어가야 하는 내용은 저장소 밖 비공개 인수인계서에 쓰고, 저장소 쪽에는 쓰지 않는다.

## 파일 순서와 지시

같은 파일을 여러 단계에서 여는 경우는 「다시」로 표시했다. 같은 crate 안에서는 타입을 정의하는 파일이 쓰는 파일보다 앞에 온다.


### 0단계 — 확인 (코드 없음)

설계서 §15의 실측·결정. 코드 없음. 결과는 설계서 §15와 구현계획서 0단계 표에 적는다.


### 1단계 — 바닥 타입과 LLM 호출


#### 1. `crates/docmodel/src/anchor.rs`

(구현됨) FileId, Rect, Anchor { source, page, bbox, path }.
규칙: Anchor 없는 값은 판정 근거가 될 수 없다. Option<Anchor>가 None인 채 Z3에 들어가는 경로를 타입으로 막는다.
「다시」(4단계, 설계서 §6.3): 사실 출처를 넓힌다.
- `enum FactSource { File(FileId), UserMessage { message_id: String } }` — `Anchor.source`를 이것으로.
- `span: Option<(u32, u32)>` — 쪽 표시 글자 안의 글자 위치(인용 대조, 설계서 §9.1).
- serde 형식이 바뀌므로 RocksDB `state`의 옛 값은 읽지 않고 다시 만든다(세션 산출물이라 지워도 된다).


#### 2. `crates/docmodel/src/block.rs`

(구현됨) Block(Heading·Para·Table), Table{cells, anchor, degraded}, Cell, Document{blocks, source, warnings}, ExtractWarning, `Table::to_markdown`.
규칙: 표를 평문으로 뭉개지 않는다. 표를 글자로 바꾸는 일은 `to_markdown` 하나만. serde 파생(RocksDB 보관). `degraded` 표는 산술 검증·Z3 입력에 쓰지 않는다.
「다시」(4단계):
- `Document::render_paged(&self) -> (String, Vec<SpanMap>)` — 쪽 표시(`--- pN ---`)가 들어간 글자와, 글자 위치 → (블록 번호, Anchor) 대응표.
  쪽 번호만 있는 줄("-1-")은 같은 길이의 공백으로 바꿔 글자 위치를 보존한다 (설계서 §6.1).
- `Document::outline(&self, max_level, max_lines)` — 목차(제목·쪽).
- `to_markdown`의 `unwrap_or(0)`은 허용(값이 없을 때의 정해진 기본값), 다른 `unwrap`은 금지 규칙에 맞춘다.


#### 3. `crates/docmodel/src/clause.rs`

(구현됨) ClauseId, Clause, `assign_clauses` — 블록을 조·항·호 단위로 묶는다(같은 번호가 또 나오면 「#2」).
쓰임이 바뀜(설계서 §6.1): 업로드 때 조항 번호를 붙이지 않는다. 대신
- 목차를 만들 때 「제N조」 단위를 제목으로 쓰고,
- 리프 판정 인용의 위치를 「제5조 제2항」처럼 사람이 읽는 이름으로 보일 때(answer.rs) 쓴다.
코드는 그대로 둔다.


#### 4. `crates/docmodel/src/clause/marker.rs`

(구현됨) 조·항·호 표시 판별(`parse_marker`). 조 「제5조」「제5조의2」(+ 같은 문단의 ①), 항 ①~⑳, 호 「1.」(점 뒤가 공백·끝일 때만 — 「1.5%」 제외).
숫자는 `[0-9]` — `\d`는 전각 숫자까지 잡는다. 정규식은 LazyLock에 한 번만 컴파일(`expect`는 컴파일 때 확정되는 상수라 허용 목록).
표시 종류가 늘면(목 「가.」, 「(1)」, 부칙·별표) 이 파일만 고친다. 오탐·누락은 실제 계약서·처분서 표본으로 잰다(구현계획서 4단계).
알려진 오탐: 「제5조 및 제6조에 따라…」처럼 조 번호 뒤에 공백이 오는 인용문.


#### 5. `crates/docmodel/src/lib.rs`

통합 문서 모델 (설계서 §6.3). 파서가 셋이어도 출력은 이 crate의 타입 하나. 순수 타입 + 순수 함수만, tokio·I/O 금지.
모든 추출 값은 Anchor를 달고 다닌다. `pub mod anchor; pub mod block; pub mod clause;`


#### 6. `crates/llm/src/lib.rs`

Rust 쪽 LLM 호출 공통층(리프 판정, 쿼리 재작성). 도구 선택·서술은 ④(LangChain) — 여기 없음.
공통 계약: temperature 0, 짧은 max_tokens, 시간 제한, 지수 backoff(횟수 제한), strict JSON(실패하면 1회 다시 요청, 그래도 실패면 오류 — 기본값을 채우지 않는다).
단계 사이에 CoT·대화 이력을 넘기지 않는다. typed 요청·응답만.
- `enum LlmError { Timeout, RateLimited, Http(u16), ParseFailed, Cancelled, Unavailable }` → engine::leaf가 FailureReason으로 바꾼다.
- `pub mod client; pub mod limits;`


#### 7. `crates/llm/src/limits.rs`

(구현됨) `LlmLimiter` — `Arc<Semaphore>`, 기본 8, `acquire() -> OwnedSemaphorePermit`(permit이 범위를 벗어나면 자동 반환).
「다시」(3·6단계, 설계서 §2.2):
- 호출하는 쪽별 상한을 따로 둔다 — 쿼리 재작성·임베딩 4, 리프 판정 판정당 8·서버 전체 12. 값은 설정으로, 이유는 설계서 §2.2.
- 리프 판정은 두 단계(판정 하나의 limiter → 서버 전체 limiter)로 permit을 잡는다.
- 대기열 감시(설계서 §2.2)가 서버 전체 상한을 절반으로 낮추고 되돌리는 `set_permits(n)`.
- `acquire`의 `unwrap`은 금지 규칙에 걸린다 — 닫힌 semaphore는 `LlmError::Cancelled`로 바꿔 `Result`로 돌려준다.
취소: CancellationToken은 호출자(leaf.rs)가 `select!`로 건다 — permit 대기 중에도 취소가 먹어야 하므로.


#### 8. `crates/llm/src/client.rs`

OpenAI 호환 `/v1/chat/completions` 클라이언트 (설계서 §2, §2.2).
- `struct LlmClient { http, base_url, api_key, model, priority }` — 주소·키·모델명은 설정(`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`).
- `async fn complete_json<T: DeserializeOwned>(&self, system, user, opts) -> Result<T, LlmError>`
  1) temperature 0, max_tokens 상한, (지원하면) JSON 출력 지시. 요청 본문에 우선순위 값(설계서 §2.2, 인자 이름은 0단계 확인)을 싣는다.
  2) 전체 마감은 `tokio::time::timeout`(대기열 대기 포함). 마감 초과는 다시 보내지 않는다(같은 요청을 대기열에 또 쌓지 않음).
  3) 연결 실패·5xx·429만 지수 backoff 재시도(기본 3회).
  4) 본문에서 JSON을 뽑아 serde 파싱. 실패하면 「JSON만 출력」 지시를 붙여 1회 다시 요청.
  5) 최종 실패는 `LlmError::ParseFailed` — 기본값 T를 만들지 않는다.
- 계측: 호출마다 지연·재시도 횟수·모델명을 tracing으로(평가 표본 실측 재료). 로그에 프롬프트 본문을 남기지 않는다(문서 내용이 들어 있다).
- 1단계 성공 기준: 가짜 응답 서버에 대고 `cargo test` — JSON 실패 → 1회 재요청 → `ParseFailed`, 429·5xx → 정해진 횟수 재시도, 마감 초과 → 재시도 없음.

#### 12. `agent/semantic_agent/memory.py`

`adelete_thread` 뒤 세 표의 해당 행 0; 하위 에이전트가 읽은 것은 메인 대화에 남지 않는다.
규칙: 한 thread_id에 실행 둘을 동시에 돌리지 않는다(sessions.py). 체크포인트 쓰기 실패는 그 질문을 Error로 끝낸다(설계서 §12). Store에는 사용자 설정만.


#### 13. `agent/semantic_agent/tools.py`

에이전트 도구 — ① Rust 내부 도구 API 호출 (설계서 §5.3, §13.3). 도구가 돌려준 문자열이 곧 「에이전트가 읽은 것」으로 세션에 저장된다.
전부 async, 공용 `httpx.AsyncClient` 하나.
- `search_laws(query, k=8, as_of=None, law_type=None)` → `POST /search/laws`
- `search_cases(query, k=8, field=None, court_level=None, decided_from=None, decided_to=None)` → `POST /search/cases`
- `read_law(law, unit, as_of=None)` → `GET /laws/unit`
- `read_case(decision_id, sections=None)` → `GET /cases/{id}`
- `case_citations(decision_id=None, law=None, unit=None)` → `GET /citations`
- `kg_find(graph, text=None, law=None, unit=None, kind=None, limit=20)` → `POST /sessions/{sid}/kg/find`
- `kg_expand(graph, node, direction, relation=None, depth=1, limit=20)` → `POST /sessions/{sid}/kg/expand`
  짧은 번호(L1…)는 그대로 넘기고 그대로 받는다. 변환은 ①이 한다(설계서 §8.3).
- `judge(claim_type, node_id, assumptions=[], user_facts=[])` → `POST /sessions/{sid}/judge`
  `user_facts`의 각 문장이 이 세션의 사용자 메시지에 글자 그대로 있는지 먼저 확인하고(설계서 §9.1), 있으면 그 메시지 ID를 붙여 보낸다.
  없는 문장은 빼고 결과 첫 줄에 「사용자 진술에서 찾지 못함: …」. 도구 설명에는 `GET /catalog`의 노드 카탈로그를 넣는다(기동 때 한 번).
- 세션 ID는 모델이 채우지 않는다: `runtime: ToolRuntime`의 `runtime.config["configurable"]["thread_id"]`(2026-09-29 확인).
- 결과 문자열 규칙: 항목마다 출처(설계서 §7.2). 강등이면 첫 줄에. HTTP 오류·시간 초과는 「검색 실패: 사유」·「판정 불가: 사유」 문자열로.
- 2단계: `fake_tools`면 설계서 §13.3 형식의 고정 문자열을 돌려준다.

#### 17. `agent/semantic_agent/sessions.py`

세션별 실행 관리 — 같은 세션은 한 번에 하나, 업로드가 진행 중인 질문보다 우선 (설계서 §11)
app.py(엔드포인트)와 나눈 이유: 동시성 규칙은 엔드포인트가 늘어나도 한 곳에서 지켜야 한다.

담을 것:
- class SessionRegistry: dict[session_id, SessionSlot] (없으면 만든다)
- class SessionSlot: lock: asyncio.Lock, running_ask: asyncio.Task | None
- async def run_ask(slot, coro) : 락을 잡고 질문 실행 태스크를 running_ask로 기록한 뒤 실행
- async def run_upload(slot, coro): running_ask가 있으면 cancel() → 끝나기를 기다린 뒤 락을 잡고 업로드

규칙:
- 한 thread_id에 실행은 하나만 (memory.py 규칙) — 같은 체크포인트에서 갈라진 두 실행 중
  한쪽 기록이 최신 상태에서 빠질 수 있다. 세션 사이는 병렬.
- 업로드는 진행 중인 ask보다 우선한다 (설계서 §11 문서 수정판 우선).
  Rust 쪽 판정은 session_actor가 업로드 도착 때 취소한다.
  취소로 답 없이 남은 도구 호출은 다음 실행 때 PatchToolCallsMiddleware(기본으로 켜짐)가 메운다.
- 오래 안 쓰인 SessionSlot은 지운다 (메모리만 — 대화 기록은 체크포인트에 남아 있다).

#### 21. `crates/retrieval/src/lib.rs`

#### 22. `crates/retrieval/src/embed_client.rs`

#### 24. `crates/retrieval/src/sql.rs`

#### 28. `crates/parsers/src/docx.rs`

DOCX 파서 — zip + quick-xml 직접 파싱 (§6.2)
기존 crate(docx-rs 등)는 쓰기 위주라 읽기가 부실 → 직접 스트리밍 파싱.

로직:
1) zip에서 word/document.xml 추출.
2) quick-xml 스트리밍으로 순회:
   - <w:p>  → Block::Para. 개요 수준이 있으면 Block::Heading { level }:
     문단의 <w:pPr><w:outlineLvl w:val="N"/> 또는 그 문단 스타일(styles.xml)의 outlineLvl을 읽어
     level = N + 1 (N은 0~8, 9는 본문). 스타일 이름("Heading 1", "제목 1")은 언어판마다
     달라서 기준으로 쓰지 않는다.
   - <w:tbl> → Table: <w:tr>/<w:tc> 순회로 Cell{row, col} 채움
3) 병합 셀:
   - <w:gridSpan w:val="N"> → colspan = N
   - <w:vMerge w:val="restart"> → rowspan 시작, 이후 <w:vMerge/>(continue)를
     만나는 동안 rowspan += 1, continue 셀은 생성하지 않음.
4) Anchor.path에 "body/p[i]" / "tbl[i]/tr[r]/tc[c]" 기록.

신뢰 등급: 최상 (구조가 XML에 명시). degraded = false 고정.

함수: pub(crate) fn parse_docx(bytes: &[u8]) -> Result<Document, ParseError>
「더할 것」: numbering.xml로 자동 번호(목록 번호·조항 번호)를 글자로 복원한다(abstractNum, lvlOverride, startOverride, lvlRestart, %N). 각주(footnotes.xml)를 읽어 본문 위치와 함께 둔다. 쪽 경계는 `lastRenderedPageBreak`·`br type=page`·`pageBreakBefore`로만 안다 — 없으면 쪽 번호를 비운다.


#### 29. `crates/parsers/src/hwpx.rs`

HWPX 파서 — zip + XML (KS X 6101), docx.rs와 같은 요령 (설계서 §6.2)

로직:
1) zip에서 Contents/section*.xml 들을 순서대로 추출.
2) quick-xml 스트리밍:
   - <hp:p> → Para. 그 문단 모양이 개요 문단이면 Heading { level } (개요 수준 + 1).
     개요 여부·수준을 담은 속성 이름은 실제 HWPX 파일(header.xml의 문단 모양)로 확인하고 적는다.
     Heading을 못 가려도 조항 묶기(docmodel::clause)는 Para의 「제N조」 표시로 동작한다.
   - <hp:tbl> → Table (<hp:tr>/<hp:tc>, 병합은 cellSpan 속성 — rowSpan/colSpan)
3) Anchor.path에 "section[i]/p[j]" 형태 기록.

주의: HWP 구형 바이너리(.hwp)는 여기서 다루지 않는다 — lib.rs의 detect가
      CFB 매직(D0 CF 11 E0)을 보면 ParseError::Unsupported(변환 안내)로 반환.

함수: pub(crate) fn parse_hwpx(bytes: &[u8]) -> Result<Document, ParseError>

checks — 결정론 검증 (설계서 §1.2, 설계서 §6.1)

- struct RawVerdict { result: 삼값(sat/unsat/unknown), core: Vec<NodeId>,

로직:
1) ★ Context는 이 함수 안에서 생성하고 함수가 끝나면 버린다 (설계서 §11 —
   스레드 간 공유 불가. 판정은 ms 단위라 매번 생성해도 비용 없음).
2) 위상정렬 순서로 노드 식 조립:
   - LEAF → Bool 상수 이름 = node_id
   - AND/OR → 자식 식들의 And(..)/Or(..)

4) assumptions(가정 질문 설계서 §9.6): 지정 노드를 고정값으로 add.

5) s.check() 삼값 그대로 반환 + unsat이면 unsat_core 수집,
   sat이고 자유변수가 있으면 model에서 값 읽기(성립에 필요한 사실 조합).

모순 검출 지원: 긍정/부정 쌍 리프 공리(unpaid == Not(paid))를 여기서 추가 —
leaf.rs가 충돌 감지→재판정→Unknown 강등을 주관한다.

#### 48. `crates/engine/src/leaf.rs`

리프 판정 (설계서 §9.1, §11, §12).
- `async fn judge_all(reqs, llm, limiter, cache, cancel) -> HashMap<NodeId, LeafResult>`
  0) NoEvidence → Unknown. 1) cache.get → 적중이면 LLM 생략(설계서 §9.7). 2) 미스만 JoinSet + LlmLimiter 두 단계(설계서 §2.2), `select!`로 cancel.
  3) 응답 JSON `{ value: True|False|Unknown, quote, source: doc|user:<fact_id> }` →
     True/False면 `locate`/`locate_user`로 인용 대조 → 찾으면 Judged{anchor}, 못 찾으면 Unknown(QuoteNotFound). LlmError는 FailureReason으로(기본값 채움 금지).
  4) 모순 검출: 긍정·부정 쌍이 둘 다 True → 1회 다시 판정 → 그래도면 둘 다 Unknown(Contradiction).
  5) cache.put — 일시 오류(시간 초과·모델 서버 무응답)는 저장하지 않는다. NoEvidence·Contradiction은 저장.
인용 대조 검사의 정확도(원문에 있는 인용을 통과시키는지, 한 글자라도 바뀐 인용을 막는지)는 6단계에서 표본으로 잰다.

#### 54. `crates/parsers/src/pdf_table.rs`

PDF 표 격자 재구성 — 신규 알고리즘 덩어리 1/2 (설계서 §6.2)
PDF에는 표 구조가 없다. 선 몇 개와 글자 좌표뿐 → 기하적으로 복원한다.
Camelot의 lattice 방식과 동일한 알고리즘을 Rust로.

입력: 페이지의 선분들(Vec<Segment>), 글자들(Vec<(char/word, Rect)>)
출력: Result<docmodel::Table, TableError>

이 파일에서 정의할 타입:
- struct Segment { x0: f32, y0: f32, x1: f32, y1: f32 }   // pdf.rs가 path 객체에서 뽑아 넘김
- enum TableError { NoGrid, TooManyUnassigned { ratio: f32 }, Ambiguous(설명) }
    실패 사유는 pdf.rs가 ExtractWarning::TableDegraded로 사용자에게 알린다.

로직 (괘선 있는 표 — 법률문서 표의 대부분):
1) 선분을 수평/수직으로 분류, 기울기 허용오차 내 스냅.
2) 가까운 좌표(허용오차 ε px)를 병합해 격자선 후보 목록 생성.
3) 수평선×수직선 교차점으로 격자 구성 → 셀 사각형 목록.
4) 이웃 셀 사이에 경계선이 없으면 병합 셀로 판정 (rowspan/colspan 계산).
5) 각 글자/단어를 bbox 중심점으로 셀에 배정, 셀 내 y→x 순 정렬로 텍스트 조립.
6) 검증: 배정 안 된 글자 비율이 임계 초과면 실패로 처리.

실패 시 (설계서 §12): Table을 만들지 않는다. 호출자(pdf.rs)가 평문 강등 +
  degraded=true 처리 → 산술 검증·Z3 입력에서 제외.
  셀 배정이 틀린 숫자가 Z3에 들어가는 것이 최악이므로, 애매하면 실패가 정답.

괘선 없는 표: 여기서 다루지 않는다. server::upload에서 페이지 렌더 →
  멀티모달 LLM 추출(신뢰 등급 하락 표시 + 페이지·좌표 인용)로 우회.

시험: 다운로드 폴더의 실제 서증·계약서 PDF 표본으로 셀 배정 정확도를
  실측한 뒤에야 저장 경로에 붙인다 (설계서 §6.2 말미).


### 8단계 — 나머지 요건 트리


#### 55. `crates/checks/src/periods.rs`

법정 기간 계산 — 기산점 날짜에서 마감일 구하기 (설계서 §9.2)
dates.rs(날짜 글자 해석)와 나눈 이유: 이 파일은 민법의 기간 규정을 옮긴 법 규칙이라,
날짜 표기 형식이 늘어나는 것과는 따로 바뀐다.

담을 것:

- fn deadline_years(start: NaiveDate, years: u32, holidays: &Holidays) -> NaiveDate
    (월 단위 기간이 필요해지면 deadline_months를 같은 방식으로)
- struct Holidays — 연도별 공휴일 목록 (상수 또는 데이터 파일). 토요일 판정 포함.

적용 규칙 — 행정소송의 기간 계산은 민법을 따른다
(행정소송법 제8조 제2항 → 민사소송법 제170조 → 민법):
- 초일 불산입: 기간의 첫날은 넣지 않는다. 다만 오전 0시부터 시작하면 넣는다 (민법 제157조).
- 주·월·연으로 정한 기간은 역에 따라 계산한다. 마지막 주·월·연에서 기산일에 해당하는 날의
  전날로 끝나고, 그런 날이 없으면 그달의 말일로 끝난다 (민법 제160조).
  → 1년을 365일로 바꿔 계산하지 않는다.
- 기간의 말일이 토요일 또는 공휴일이면 그다음 날로 끝난다 (민법 제161조).

제소기간 (행정소송법 제20조) — 여기서는 기산점을 받아 마감일만 돌려준다.
어느 기산점을 쓸지는 요건 트리($DATA_DIR/rules/claim_취소소송.yaml)가 정한다:
- 처분등이 있음을 안 날부터 90일 (제1항), 처분등이 있은 날부터 1년 (제2항)
- 행정심판을 청구한 경우: 90일은 재결서 정본을 송달받은 날부터 (제1항 단서),
  1년은 재결이 있은 날부터 (제2항 괄호)
- 정당한 사유가 있으면 1년이 지나도 제기할 수 있다 (제2항 단서) — 계산이 아니라 리프 판정

쓰임: engine이 ArithSpec(WithinDays·WithinYears)의 마감일을 여기서 구해 ordinal로 Z3에 넣는다.
      Finding을 내는 검증이 아니라 계산 도구라 run_all에는 들어가지 않는다.
규칙: Z3·LLM에 달력 계산을 시키지 않는다.

| 리프 판정 | 동시 8, 사실 묶음은 `Arc<str>`로 나눠 씀(리프마다 복사 금지) | 같은 문서 전문을 리프 수만큼 복사하지 않기 |
| ④ Python | 상주 1GB 목표 | deepagents + 체크포인트 |
| ⓪ 창구 | 200MB | 걸러 보내기만 |
| PostgreSQL(이 PC에 둘 때) | shared_buffers 1GB, work_mem 16MB, max_connections 40 | 앱 DB는 작다 |

규칙:
- 큰 것은 흘려 처리한다: 업로드 zip 항목, JSONL 적재, SSE 전달. 통째로 메모리에 올리지 않는다.
- 큰 값은 복사하지 않고 `Arc`·`Bytes`로 나눠 쓴다. 문서 글자는 `Arc<str>`.
- 메모리 감시: ①·⓪가 30초마다 시스템 사용 가능 메모리를 읽어 1GB 아래면 새 업로드·새 judge를 「잠시 뒤 다시 시도해 주세요」로 거절(사유는 로그에만).
- 할당기: 기본 할당기로 시작하고, 4단계 부하 시험에서 상주 메모리가 상한을 넘거나 조각화가 보이면 mimalloc을 붙인다(그때 값을 여기 적는다).
- ④: 2만 토큰 넘는 도구 결과는 파일로 빠짐(deepagents 기본), 요약은 문맥 한도의 85%(기본). 체크포인트 하나의 크기를 4단계에서 잰다.
- 끝: 4·6단계 부하 시험(업로드 2건 + judge 1건 + 질문 3건 동시)에서 각 프로세스 최고 상주 메모리를 재어 표에 적는다.

참고: Cargo Book 「Package Layout」(lib.rs·main.rs·tests/·benches/), Rust API Guidelines, 평평한 `crates/` 작업 공간(큰 Rust 작업 공간의 흔한 관례), 포트와 어댑터(바깥 기능을 트레이트로 받는 engine의 deps), PyPA 「src layout」, React의 기능별 폴더.

│  ├─ server/  gateway/  ruleloader/  xtask/ # 실행 파일
│  └─ <crate>/src/{lib.rs|main.rs, error.rs, …}, <crate>/tests/

│  ├─ src/semantic_agent/
│  │  ├─ config.py
│  │  ├─ api/      app.py  sessions.py  sse.py          # 내부 HTTP(⓪만 부름)
│  │  ├─ agent/    build.py  prompts.py  context.py  guards.py

crate 안의 규칙:
- `lib.rs`(`main.rs`)는 모듈 선언과 공개 항목 다시 내보내기만. 로직을 두지 않는다.

- 오류 타입은 crate마다 `error.rs` 하나.
- 의존 방향은 아래로만(실행 파일 → engine → 바깥 기능 → 순수). 거꾸로 부르지 않는다. 순환이 생기면 트레이트로 끊는다.
- 바이너리 crate의 HTTP 경로는 `http/` 아래 묶음마다 파일 하나(`http/search.rs`, `http/upload.rs`, …), 기동·설정·상태는 `main.rs`·`config.rs`·`state.rs`.
- 시험: 단위 시험은 그 파일 안 `#[cfg(test)] mod tests`, 통합 시험은 `<crate>/tests/`.
